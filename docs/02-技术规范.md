## 1. 架构

### 1.1 分层

```
┌──────────────── UI 层（Jetpack Compose + Material 3） ─────────────────┐
│ 库浏览 · 搜索 · 排序/筛选 · 详情页 · 播放器页(控制器 + 预览条) · 设置 · 锁屏 │
├──────────────── 领域层（纯 Kotlin，无 Android 依赖） ──────────────────┤
│ MediaSourceRepository · SortEngine · SearchEngine                       │
│ PlaybackNegotiator · PlaybackState · ProgressSync                       │
├──────────────── 数据层 ───────────────────────────────────────────────┤
│ Room(元数据缓存/索引/本地进度) · DataStore(设置) · 文件(加密凭据/令牌)    │
│ Coil(图片与 trickplay 分片缓存)                                        │
├──────── 源适配层（同一接口，多种实现） ────────────────────────────────┤
│ EmbySource       │ JellyfinSource(飞牛 :8005) │ LocalSource(L2)         │
├──────────────── 播放层（Media3） ─────────────────────────────────────┤
│ PlaybackEngine(ExoPlayer) · HLS(转码/重封装) · FFmpeg 音频扩展          │
│ MediaSessionService · PiP                                              │
└───────────────────────────────────────────────────────────────────────┘
                  ↕ OkHttp + kotlinx.serialization
         Emby 服务器        飞牛影视 :8005        本机 MediaStore / SAF
```

### 1.2 依赖规则（硬约束）

| 规则 | 说明 |
|---|---|
| 单向向下 | `feature → source / core → core:model`，不允许反向依赖 |
| `:source:*` 之间**互不依赖** | 新增一种源（Plex、SMB）= 新增一个模块 + 改一处装配点 |
| `:core:model` 纯 Kotlin | 无 Android 依赖，可在 JVM 单元测试中直接驱动 |
| 装配点唯一 | 把「服务器配置」变成 `MediaSource` 的地方**只有** `SourceFactory`（见 §3.2） |
| UI 不含业务规则 | 排序 / 筛选 / 搜索 / 协商逻辑都在领域层，Compose 只负责渲染状态 |

### 1.3 塑造了架构的关键结论

| 结论 | 对架构的影响 | 依据 |
|---|---|---|
| 飞牛影视使用 **Jellyfin 兼容协议** | Emby 与飞牛**共用一套 REST 骨架 + 两个薄适配层**，而非两套客户端 | [`05`](05-接口契约.md) §5 |
| 服务端 `SortBy` **不含文件大小 / 码率 / 分辨率** | 「按文件大小排序」只能在**客户端**做 → 需要完整落库与 `SortEngine` | [`05`](05-接口契约.md) §2.3 |
| 服务端搜索**对中文几乎无效** | 搜索以**客户端本地索引（FTS4 + 拼音）为主**，服务端仅兜底 | §6.5 |
| `PlaybackInfo` 的 `TranscodingUrl` 是**相对路径** | 播放层拿到后必须与 `baseUrl + prefix` 拼接，否则无法播放 | [`05`](05-接口契约.md) §2.4 |
| 三类源的时间单位不同（tick / ms） | 领域层统一 `Ticks`，只在边界互转 | §4.4 |
| 本机文件**没有服务器转码兜底** | 播放内核抽象为 `PlaybackEngine`，为 L2 平行接入 libmpv 预留 | §10 R2 |

| 图片 | Coil（内存 / 磁盘缓存，复用为 trickplay 分片缓存） |

| 编译目标 | `compileSdk 37`（Compose 2026.09 起要求）· `targetSdk 36`（Google Play 自 2026-08-31 起的底线）· `minSdk 26` · JDK ≥ 17 |

### 2.1 版本与仓库管理规则

**已锁定的版本**（2026-10-16 从官方仓库 `maven-metadata.xml` 实测取回，同一份值写在 `gradle/libs.versions.toml`）：

| 项 | 版本 | 备注 |
|---|---|---|
| Kotlin | 2.4.21 | |
| AGP | 9.4.1 | 要求 JDK ≥ 17、Gradle ≥ 9.3.x |
| Gradle | 9.8.1 | 由 `gradle/wrapper/gradle-wrapper.properties` 控制（而不是 `gradle.properties`） |
| Compose BOM | 2026.09.00 | 要求 `compileSdk 37` |
| Room / Hilt / KSP | 2.8.5 / 2.60.1 / 2.3.12 | 代码生成插件，分别在任务 1-3 / 1-12 首次启用 |

**规则**

1. 依赖版本只写在 `gradle/libs.versions.toml`，模块构建脚本里**不写版本号**。
2. **KSP 自 2.x 起改为独立版本号**，不再带 `2.4.21-2.0.x` 那种「Kotlin 版本前缀」。但它仍受 Kotlin 版本约束：升级 Kotlin 时必须一并复核 KSP（本项目首次启用它是在任务 1-3）。
3. Compose BOM 与 AGP 的最低版本要求，取两者中**较高者**。
4. `targetSdk` **只在 `:app` 声明**（库模块声明它无效）：缺省时 AGP 会跟随 `compileSdk`，等于把 App 标成面向最新 API，新系统的行为变更会在无预期的情况下生效。
5. **不使用 `jvmToolchain(...)`**，改用 `kotlin { compilerOptions { jvmTarget = JvmTarget.JVM_17 } }`：前者要求本机恰好装有该版本 JDK，装了更高版本反而报「No matching toolchains」。
6. **依赖「是否存在」必须实测**，不能凭记忆 —— 本项目已踩过：原计划指定的 TinyPinyin 只发布在已关停的 JCenter，Maven Central 返回 404，已改用 pinyin4j。
7. **AGP 9 起 Kotlin 编译已内置（built-in Kotlin），不能再应用 `org.jetbrains.kotlin.android` 插件** —— 否则构建直接失败：
   > `The 'org.jetbrains.kotlin.android' plugin is no longer required for Kotlin support since AGP 9.0.`
   
   连带的三条规则（依据官方迁移指南 `developer.android.com/build/migrate-to-built-in-kotlin`，国内用 `developer.android.google.cn` 打开）：
   - Android 模块的 `plugins {}` 里**不要**写 `kotlin-android`，`libs.versions.toml` 里也不要再有这个插件条目；
   - **`jvmTarget` 不需要配置** —— 内置 Kotlin 默认取 `android.compileOptions.targetCompatibility`；
   - `org.jetbrains.kotlin.plugin.compose` 等**编译器插件仍然照常应用**；纯 JVM 模块（`:core:model`）不受影响，继续用 `org.jetbrains.kotlin.jvm` + `kotlin { compilerOptions { jvmTarget = … } }`。
   
   > 想回退旧行为可以设 `android.builtInKotlin=false` + `android.newDsl=false`，但 AGP 10 会移除该开关 —— 不要走这条路。

**国内镜像**（已配好，无需手动改）

| 内容 | 配在哪 | 源 |
|---|---|---|
| Gradle 发行包 | `gradle/wrapper/gradle-wrapper.properties` | 华为云 `mirrors.huaweicloud.com/gradle/`（sha256 已与官方 `gradle-9.8.1-bin.zip.sha256` 比对一致） |

**约定**（已在 1-0 落地）

- 包名 / namespace 前缀统一 **`app.myplayer`**（`:app` 的 `applicationId` 同值），与 `reference/` 里的参考实现保持一致，不另起名字。
- M1 只建上述表里的 12 个模块；其余模块（`:core:playback`、`:source:jellyfin`、`:source:local`、`:feature:search/detail/player/settings`）在各自的里程碑引入，**不提前建空壳**。

### 3.2 装配点：`SourceFactory`

- 位置：**`:feature:server`**（不能放 `:source:*`，因为 `:source:*` 之间不允许互相依赖，而它需要同时知道 Emby 与 Jellyfin）。
- 输入：一个 `ServerConfig`（含 id、类型、baseUrl、userId）。
- 输出：可用的 `MediaSource`，**或者 `null`**。
- **返回 `null` 的语义**：令牌或 userId 缺失 → 视为「需要重新登录」，UI 应回到登录流程；**不允许**返回一个会在首次请求时才抛错的半成品 source。
- 新增源类型的改动面：加一个 `:source:*` 模块 + 在 `SourceFactory` 加一个分支，**上层 UI 不动**。

## 4. 领域模型契约

> 字段的类型与单位是**契约**。新增字段需要同时更新本表、`05` 的字段映射，以及数据库表结构。

### 4.1 枚举

| 类型 | 取值 | 说明 |
|---|---|---|
| `SourceType` | `EMBY` / `JELLYFIN` / `LOCAL` | 飞牛影视用 `JELLYFIN` |
| `ImageKind` | `POSTER` / `BACKDROP` / `THUMB` / `LOGO` | |
| `ImageSize` | `SMALL(200)` / `MEDIUM(400)` / `LARGE(800)` | 值即请求的 `maxWidth`（px） |
| `PlayState` | `PLAYING` / `PAUSED` / `STOPPED` | 进度上报用 |

### 4.2 `MediaItemDto`（三源统一，供展示与本地排序）

| 字段 | 类型 | 单位 / 取值 | 来源 | 可空 |
|---|---|---|---|---|
| `id` | `String` | 源内唯一 | Emby `Id` / MediaStore `_ID` | 否 |
| `serverId` | `String` | — | 本地生成（多服务器区分，Room 主键组成部分） | 否 |
| `sourceType` | `SourceType` | — | 由适配器决定 | 否 |
| `title` | `String` | — | `Name` | 否（缺省空串） |
| `seriesName` | `String?` | — | `SeriesName` | 是 |
| `seasonNumber` / `episodeNumber` | `Int?` | — | `ParentIndexNumber` / `IndexNumber` | 是 |
| `durationTicks` | `Ticks` | **100ns tick** | `RunTimeTicks` | 否（缺省 `Ticks.ZERO`） |
| `sizeBytes` | `Long?` | 字节 | `MediaSources[].Size` | 是 |
| `bitrate` | `Int?` | bit/s | `MediaSources[].Bitrate` | 是 |
| `width` / `height` | `Int?` | px | `MediaSources[].Width/Height` | 是 |
| `videoCodec` | `String?` | 如 `hevc` | `MediaSources[].VideoCodec` | 是 |
| `audioCodecs` | `List<String>` | 如 `["dts","ac3"]` | `MediaSources[].AudioCodec` | 否（可空列表） |

| `communityRating` | `Float?` | 0–10 | `CommunityRating` | 是 |
| `officialRating` | `String?` | 如 `PG-13` | `OfficialRating` | 是 |
| `playCount` | `Int` | 次数 | `UserData.PlayCount` | 否（缺省 0） |
| `userData` | `UserData` | 见 §4.3 | `UserData` | 否 |
| `hasPoster` | `Boolean` | — | 由 `ImageTags.Primary` 派生 | 否（缺省 false） |
| `genres` | `List<String>` | — | `Genres` | 否 |

**派生行为**：
- `resumeFraction(): Float` = `resumePositionTicks / durationTicks`，`durationTicks` 为 0 时返回 0，结果裁剪到 `[0,1]`。
- `hasPoster = false` ⇒ `image()` **必须**返回 `ImageSource.None`（不允许发一个必然 404 的图片请求）。

### 4.3 `UserData`

| 字段 | 类型 | 单位 | 缺省 |
|---|---|---|---|
| `isPlayed` | `Boolean` | — | false |
| `resumePositionTicks` | `Ticks` | 100ns tick | `Ticks.ZERO` |
| `isFavorite` | `Boolean` | — | false |

### 4.4 时间单位口径（`Ticks`）

- `Ticks` = `@JvmInline value class Ticks(val value: Long)`，1 tick = 100ns，1 秒 = 10,000,000 ticks。
- **领域层一律用 `Ticks`**：`MediaItemDto`、`UserData`、进度计算。
- **只在两个边界转成 `Long` / ms**：
  1. **Room 边界**：实体字段仍是 `Long`（避免依赖 Room 对 inline class 的支持），在 `Mappers` 中显式 `.value` / `Ticks(...)`；
  2. **播放层边界**：`reportProgress(pos: Duration)` 面向 ExoPlayer（ms），转换函数在 `:core:playback` 内。
- **禁止**在跨模块传值时用裸 `Long` 表示时间；若某处确实必须用 `Long`，**必须写单位注释**。

### 4.5 其余模型契约

| 类型 | 契约 |
|---|---|
| `MediaLibrary` | `id` / `name` / `itemCount: Int?`（库条目数）/ `collectionType: String?`（如 `movies`）——后两者供库 Tab 展示，取自 `/Views` |
| `ItemQuery` | `libraryId` / `searchTerm?` / `startIndex` / `limit`（默认 200）/ `includeItemTypes`（默认 `Movie, Series, Episode, Video`） |
| `PagedResult<T>` | `items` / `totalCount` / `startIndex`；`hasMore = startIndex + items.size < totalCount` |
| `ImageSource` | `Remote(url, headers)` / `Local(uri)` / `None`。**令牌只放 `headers`，不进 URL** |
| `PlaybackPlan` | `Direct(uri, headers, mediaSourceId?)` / `Transcode(hlsUrl, headers, isRemuxOnly)`。`Transcode.hlsUrl` 必须是**绝对 URL** |
| `ClientCapabilities` | 声明支持的视频 / 音频编码集合、最大宽高、是否支持 HDR、设备名与设备 ID；用于构造 `DeviceProfile` |
| `TrickplaySpec` | `width` / `tileWidth` / `tileHeight` / `tileCount` / `intervalMs` / `playlistUrl` |

## 5. 媒体源接口契约

### 5.1 方法契约

| 方法 | 输入 | 输出 | 失败模式与约定 |
|---|---|---|---|
| `type` | — | `SourceType` | — |
| `serverId` | — | `String` | 用于多服务器区分 |
| `getLibraries()` | — | `List<MediaLibrary>` | 走 `/Users/{userId}/Views`（见 `05` §2.2）；**userId 缺失时必须立即报错**，不允许拼出 `/Users/null/...` |
| `getItems(query)` | `ItemQuery` | `PagedResult<MediaItemDto>` | 列表查询**不请求 `People`**（重字段留给详情页） |
| `getItemDetail(id)` | itemId | `MediaItemDto` | 详情页才取演职员等重字段 |
| `image(item, kind, size)` | | `ImageSource` | `item.hasPoster == false` 且 `kind == POSTER` ⇒ 返回 `None` |
| `planPlayback(item, caps)` | | `PlaybackPlan` | 决策表见 §6.1；**不允许**在三档都不满足时硬回退成直连 |
| `getTrickplay(item, width)` | | `TrickplaySpec?` | 返回 `null` 表示不可用 ⇒ 走降级（不禁用播放） |
| `reportProgress(item, pos, state)` | `Duration`(ms) | — | 本地源为空实现 |

### 5.2 参数前置校验（防止难查的 404）

`userId` 是取数与播放的**前置条件**。以下方法在 `userId` 为空时**必须立刻失败并给出明确消息**，不允许发出请求：

`getLibraries` / `getItems` / `getItemDetail` / `planPlayback`

保证方式：登录成功后**先落盘 `userId` 与令牌**，再由 `SourceFactory` 构造 `MediaSource`（顺序不可颠倒）。

### 5.3 适配差异承载方式

- 共享骨架负责：URL 拼接（`baseUrl + prefix`）、鉴权头形态、序列化、错误映射、三档播放协商、图片 URL。
- 子类只负责：`mapItem(dto, libraryId)` 与 `buildDeviceProfile(caps)`。
- 差异参数（路径前缀、鉴权头形态）通过构造时的配置对象传入，**不改基类**；

## 6. 关键机制规格

### 6.1 播放协商（直放优先、转码兜底）

```
planPlayback(item, caps):
  1. 取 PlaybackInfo（携带 DeviceProfile，声明支持的容器/视频/音频/字幕能力）
  2. SupportsDirectPlay                     → Direct(原文件流)
  3. TranscodingUrl 非空                     → Transcode(拼接后的绝对 URL, isRemuxOnly = SupportsDirectStream)
  4. SupportsTranscoding 但无 TranscodingUrl → Transcode(自拼 /Videos/{Id}/master.m3u8, isRemuxOnly = false)
  5. 以上都不满足                            → 抛错 → 错误态（§6.1.1）
  LOCAL 源                                  → 恒为 Direct(content://)
```

**6.1.1 第 5 档禁止「兜底成直连」**
服务端明确声明既不支持直放也不支持转码时，把原文件流硬塞给播放器只会失败，且失败原因极难定位（表现为「某些视频就是播不了」）。必须明确报错并展示诊断信息。

**6.1.2 其余规则**
- 字幕优先客户端渲染（避免烧录）；无法还原样式的格式（如精细 ASS）才考虑服务器烧录。
- 用户可手动强制「直放」/「转码」，用于排查与体验对比。

### 6.2 无卡顿 seek（痛点 2）

前提判断：官方 App 的约 1 秒卡顿**大概率来自转码流重启**，而非「点击进度条」本身慢。据此：

| 规则 | 要求 |
|---|---|
| 强制直放优先 | 先按客户端能力协商，能直放就不转码 |
| 乐观更新 | 点击进度条 → 立即更新 UI 位置 → 异步 seek，UI 不等网络 |
| 关键帧对齐 | 使用 `SeekParameters.CLOSEST_SYNC` + `setAllowWaitForFirstFrame`，避免精确 seek 触发大量解码 |
| 分段而非重启 | 必须转码时用 `StartTimeTicks` 请求新分段，而非整路重启转码会话 |
| 拖动不 seek | 拖动全程只更新预览，**松手才提交一次 seek**（把 N 次起流压缩成 1 次） |
| 缓冲策略 | `DefaultLoadControl` 调参（增大 `bufferForPlaybackAfterReblockMs`、`maxBufferMs`）；本地 URI 与局域网直连走 `ProgressiveMediaSource` |

### 6.3 本地排序与筛选（痛点 3）

- 同步策略：分页拉全量 `MediaItemDto` 落 Room（前台可见页优先，后台增量补全）；**同步落库的同时构建搜索索引**（§6.5）。
- 排序维度（本地）：时长、文件大小、码率、分辨率、添加时间、评分、播放次数、首播年份、标题；支持主序 + 次序（如「时长降序 + 标题升序」）。
- 筛选维度：类型（电影 / 剧集 / 集数）、演员、年份区间、分辨率区间、未看 / 已看 / 在看、收藏、源。
- 性能要求：在已同步的本地索引上**瞬时完成，不出现 loading**。
- 服务端排序（`SortBy=Runtime` 等）仅用于减少同步量，**客户端排序是唯一事实来源**。

### 6.4 进度同步

| 时机 | 行为 |
|---|---|
| 开始播放 | `POST /Sessions/Playing` |
| 播放中 | 每 10s `POST /Sessions/Playing/Progress` |
| 暂停 / 退出 / 切后台 | **立即**上报 |
| 上报失败或离线 | 写入 Room 待补队列，恢复网络后批量补报 |

前台服务 `MediaSessionService` + 通知栏 + 画中画，避免系统杀进程导致进度丢失。

### 6.5 搜索（中文友好，痛点 6）

**问题本质**：服务端索引按「词」做前缀 / 包含匹配，中文无空格切分，多数只索引 `SortName`（常为拼音或去冠词的英文）→ 中文基本搜不到。**因此以客户端本地索引为主。**

| 通道 | 数据 | 用途 |
|---|---|---|
| **主**：本地索引（Room） | 同步落库时构建的中文友好索引 | 默认通道：中文任意位置子串、拼音全拼、拼音首字母 |
| 辅：服务端 `SearchHints` | 服务端索引 | 本地未命中 / 首次同步未完成时兜底 |

**索引构建规则**
1. 字段来源：标题、原始标题 / 别名、系列名、演员、导演、类型、标签、工作室、简介（截断）。
2. 归一化：`NFKC`（全角→半角）+ `lowercase` + 去标点空白；可选繁→简。
3. 拼音：全拼（`三体` → `santi`）+ 首字母（`st`），用 **pinyin4j**（见 §2.1 的依赖实测说明）。
4. **中文逐字分词**：在 CJK 字符之间插入空格后再写入 FTS 列（`三 体`），配合 SQLite **FTS4 `unicode61`** 把每个汉字切成独立 token → 支持**任意位置子串命中**。
5. 实现取舍：库量级为数千～数万条，优先 FTS4；在普通表上保存含拼音的 `searchText` 列并用 `LIKE '%…%'` 作为**异常降级路径**。

**查询与排序**
1. 输入同样归一化 → 生成多路 query（原始子串、拼音全拼、拼音首字母、中文逐字切分）→ 合并去重。
2. 权重：标题 > 别名 / 原名 > 系列 > 演员 / 导演 > 类型 / 标签 > 简介；同权重按播放次数 / 添加时间。
3. debounce 200ms、输入即搜；过期查询必须被取消，避免结果错序。
4. 结果复用库页网格与 §6.3 的排序 / 筛选。
5. 索引未就绪时回退服务端并在顶部提示「本地索引仍在构建，结果可能不全」。
6. **不做**「优先信服务端」策略——中文命中差是服务端固有缺陷。

### 6.6 应用锁安全规格

| 项 | 要求 |
|---|---|
| 默认方案 | 九宫格图案，**至少 4 点**；保存时拒绝弱图案（Z / L / 直线等共线连线） |
| 叠加解锁 | PIN（4–8 位）；生物识别作为**快捷解锁**，失败自动回落图案 |
| 凭据存储 | 图案 / PIN **不以明文保存**。对称密钥交由 Android Keystore 保护；凭据经 `PBKDF2`（或 Argon2）加盐派生后存入加密文件；图案**只保存轨迹的哈希**，无法反推 |
| 防暴力 | 连续 5 次失败起递增冷却：30s → 1min → 5min；失败次数与时间戳加密存储 |
| 找回 | 可配备用 PIN；未配置则仅能清除应用数据重置（设置页必须明确警告） |
| 触发时机 | ① 冷启动；② 从后台回前台（超过宽限期，默认立即）；③ 手动「立即锁定」 |
| 实现约束 | 自研 Compose 九宫格组件，不引入 GPL 第三方锁库；**设置未加载完时按「已锁定」处理**（宁可多解一次，不漏锁一帧） |
| 权限 | 不需要任何运行时权限 |

### 6.7 后台行为与最近任务

| 项 | 要求 |
|---|---|
| 默认 | 切到后台（锁屏、切走、进入最近任务均视为后台）**立即暂停播放** |
| 保持后台播放 | 设置项，默认**关闭**；开启后由前台服务 + 通知栏 + 画中画承载 |
| 与应用锁的交互 | 回前台后**先解锁、再恢复播放**，避免在锁屏界面直接暴露播放控制 |
| 最近任务快照 | 保留为**当前播放内容**（画面 / 封面 + 标题），而非库列表或启动页 |
| 返回行为 | 从最近任务或后台返回时，**回到播放器页并停在当前内容**，不跳回库列表 / 启动页 |
| 任务快照隐私 | 默认**保留当前播放内容**；「后台遮挡任务快照」默认关闭 |
| 实现要点 | 播放页保持为顶栈 Activity，不因切后台而 `finish`；不调用 `setRecentsScreenshotEnabled(false)` |

### 6.8 trickplay 降级链

```
getTrickplay(item, width)
  ├─ 服务端可用 → 拉 tiles.m3u8，解析出精灵图分片列表（不逐个请求 jpg）
  │                拖动时：时间 → (分片序号, 图内行列偏移) → 从已解码 bitmap 直接切片（零网络、零解码）
  │                预取：播放开始后后台预取前后 N 个分片，LRU 缓存（复用 Coil 的 MemoryCache）
  └─ 不可用 / 本地源 → 仅显示时间气泡
                      若用户开启「本地生成缩略图」→ 按需抽帧并缓存到应用私有目录
```

## 7. 数据层契约

### 7.1 表结构

| 表 | 主键 | 关键字段 | 索引 |
|---|---|---|---|
| `libraries` | `(serverId, libraryId)` | `name` / `collectionType` / `itemCount` | — |
| `media_items` | `(serverId, itemId)` | 与 `MediaItemDto` 对齐；列表字段（`audioCodecs`/`genres`/`cast`）用不可见分隔符编码为单列；`sortTitle` 用于默认排序 | `serverId` / `libraryId` / `sortTitle` |
| 搜索索引（M3） | — | FTS4 虚表（`unicode61`，中文逐字分词 + 拼音），另有 `searchText` 作降级 | FTS |

**约定**：
- 实体中的时间字段是 `Long`（单位 tick），与领域层的 `Ticks` 在 `Mappers` 中显式互转（§4.4）。
- 列表字段的编码分隔符必须用**不可见控制字符**（如 `\u0001`），不能用 `,`——标题与演员名里都可能有逗号。

### 7.2 同步策略

| 规则 | 要求 |
|---|---|
| 分页 | 每页 200 条循环拉取；**先处理空页，再累加偏移，最后判 `hasMore`**（避免 `TotalRecordCount` 偏大时空转） |
| 优先级 | 前台可见页优先，其余后台增量补全 |
| 幂等 | 以主键 upsert，重复同步不产生脏数据 |
| 删除 | 支持按 `serverId` 整源清理（移除服务器时） |
| 离线 | 读 Room 快照并标注「离线」 |

## 8. 网络与权限

### 8.1 网络契约

| 项 | 要求 |
|---|---|
| 超时 | 连接 15s / 读 30s（局域网场景足够，且不会让用户等到怀疑卡死） |
| 错误映射 | `401/403 → Unauthorized`（认证失败）· `404 → NotFound`（资源不存在 / 端口或前缀不对）· `5xx → ServerError`（带原文）· 其他 → `Unknown` |
| 明文 HTTP | **默认关闭**；实现上用 `networkSecurityConfig` 白名单，**不要**在 Manifest 里把 `usesCleartextTraffic` 写死为 true。1-0 已按构建类型落地：release 不开明文，debug 通过 `src/debug/AndroidManifest.xml` + `src/debug/res/xml/network_security_config.xml` 放行（连局域网 `http://192.168.x.x:8096` 与 M0 抓包都需要）；P5 再改由设置项 `allowCleartextHttp` 控制 |
| 自签证书 | 默认关闭，需用户显式开启；debug 构建额外信任**用户安装的 CA**，这样抓包工具（Charles / mitmproxy）能直接解密 HTTPS，服务于 M0 的接口验证 |
| 图片鉴权 | 走请求头（Coil 注入），**不进 URL**——避免令牌进入磁盘缓存键与日志 |
| 播放流鉴权 | 用 `api_key` 查询参数（交给 ExoPlayer / HLS，形态最稳） |

### 8.2 权限清单

| 权限 | 用途 | 申请时机 |
|---|---|---|
| `INTERNET` | 访问媒体服务器 | 安装时 |
| `READ_MEDIA_VIDEO`（API 33+）/ `READ_EXTERNAL_STORAGE`（≤32） | 本机视频（L2） | 仅当用户启用「本机视频」时 |
| SAF 持久化 URI 授权 | 本机自定义目录（L2） | 用户选择目录时。**不申请 `MANAGE_EXTERNAL_STORAGE`** |
| `POST_NOTIFICATIONS`（API 33+） | 媒体通知 | 首次需要展示通知时 |
| `FOREGROUND_SERVICE_MEDIA_PLAYBACK` | 后台播放（默认关闭） | 安装时 |

**合规声明**：仅个人使用 / 开源；不内置任何内容源；不做账号体系。

## 9. 硬约束清单（Do / Don't）

> 这一节写给实现者与 AI 代理：**逐条都是踩过或推演过的坑**。

**架构**
- ✅ 依赖必须单向：`feature → source / core → core:model`。
- ❌ `:source:*` 之间不得互相依赖；`SourceFactory` 只能放在 `:feature:server`。
- ❌ 领域层不得引入 Android 依赖。

**时间与单位**
- ✅ 领域层时间一律 `Ticks`；Room 实体用 `Long` 并在 `Mappers` 显式转换。
- ❌ 禁止用裸 `Long` 跨模块传时间而不写单位注释。

**接口调用**
- ✅ 取媒体库列表走 `/Users/{userId}/Views`。
- ❌ 不要用 `Items + IncludeItemTypes=CollectionFolder` 代替；不要把 `People` 放进列表查询的 `Fields`。
- ✅ `userId` 为空的取数 / 播放调用必须**立即失败**，不能拼出 `/Users/null/...`。
- ✅ `TranscodingUrl` 是相对路径，**必须**与 `baseUrl + prefix` 拼接。
- ✅ 图片 `hasPoster == false` 时返回 `ImageSource.None`，不发必然 404 的请求。

**播放**
- ❌ 三档协商都不满足时**不得**回退成直连——明确报错。
- ✅ 拖动进度条全程不 seek，松手才提交一次。
- ✅ 旋转屏幕不得重建播放器实例。

**存储与安全**
- ✅ 令牌与服务器配置**必须密文落盘**；明文不得出现在磁盘、URL 或日志里。
- ✅ Room 列表字段用不可见控制字符编码，不能用常见分隔符。
- ✅ DataStore 读取必须捕获 `IOException`，损坏时退回默认值而不是让整条 Flow 崩掉。

**数据层**
- ✅ 分页循环先判空页、再累加、最后判 `hasMore`。
- ✅ 主键 upsert 保证重复同步幂等。

**版本与构建**
- ✅ `targetSdk` 显式声明；依赖版本只写在 `libs.versions.toml`；KSP 前缀等于 Kotlin 版本。

**界面**
- ✅ 所有可点元素热区 ≥ 48dp；所有交互带 ≤300ms 微动画。
- ❌ 不做常驻筛选条、不并排平铺播放设置按钮（详见 `03`）。
