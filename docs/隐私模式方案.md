# LimePlayer「隐私模式」方案（v2）

> 状态：规划定稿 v2（吸收安全评审 P0/P1，强化落地一致性）。待实现。
> 最后更新：2026-10-28
>
> **v1→v2 增量**（均不改已对齐的核心决策，只补落地细节）：
> - 会话结束 = 停止隐私播放 + 清 MediaSession/通知 + 关连接 + 取消费 + 清缓存 + 清 DEK（P0#1）
> - 统一可见性策略层，所有数据入口强制过滤，档二历史/进度/续播需 join 或冗余 `isPrivate`（P0#2）
> - 泄露面全清单：缓存/缩略图/下载/通知/剪贴板/输入法/Autofill/SavedState/日志崩溃（P0#3）
> - 加密格式规范：严格 encrypt‑then‑MAC、HKDF 派生、AAD 绑定、版本化封装、常数时间比较、重设 PIN 删旧封装（P0#4）
> - KEK‑DEVICE 可用性检测与降级（P0#5）
> - 备份范围扩展到 `noBackupFilesDir` + cloud/device‑transfer 双排除，Room/DataStore 评估（P0#6）
> - 迁移事务 + 退出/移入时取消任务关连接（P0#7）
> - Room 复合索引、MediaSession 彻底占位、验证界面防窥、退出防误触、多窗口/PiP 策略、威胁模型（P1）

## 一、目标与范围

**要做（v1）**
- **防窥/应用锁**：进入隐私需独立验证；隐私模式下禁截图/录屏、最近任务缩略图变空白。
- **隐私源（配置级）**：配好的 Emby / Jellyfin / 飞牛 / **SMB 连接配置**平时不可见、不可选、凭据不暴露；进隐私后才显出。
- **隐私文档（条目级）**：SMB 扫出的具体视频文档可单独标隐私，普通模式下列表/首页/续播只显示其余的。
- **隐藏式入口**：界面无「隐私」按钮，靠隐蔽手势进入。
- **隐私会话强清理 / 统一可见性 / 泄露面收敛 / 加密格式规范 / 恢复钥匙可用性 / 备份收敛**（本版新增，均为 v1 必做）。

**不做（v1 明确排除）**
- **隐身播放**：不记录历史 / 进度 / 最近观看（用户明确不纳入）。但隐私播放**仍写历史/进度**，只是所有历史/续播入口必须按 §六 统一可见性过滤，确保退出隐私后普通模式不会从全局历史漏出私文档。
- **条目级在线源隐私**：Emby/Jellyfin/飞牛 的条目不单独标隐私，它们靠「藏整源」即可。
- **LOCAL 本地源专属逻辑**：本地视频现 P3 未实现，本次只加 `file_media_items.isPrivate` 列（SMB 文档级需要），不写本地专属标记 UI，等 P3 零改动可用。

## 三、核心模型：两档独立隐私

隐私由**两档互不影响**的开关组成，不是「一个总开关」：

### 档一 · 配置/源级隐私 —— `ServerConfig.isPrivate`（DataStore）

针对「配置的源」实体（`core/datastore/ServerConfigStore.kt` 的 `ServerConfig`：
`id / sourceType / name / baseUrl / userId`）。

覆盖对象：Emby / Jellyfin / 飞牛 **以及 SMB 的连接配置**（SMB 本就是一条 `ServerConfig`，密码在 `TokenStore` 按 `serverId` 关联）。

- 标了隐私 → 普通模式下整条源：不可见、不可选、设置里不显示、凭据不暴露。
- 进隐私模式后：显出，可增删改、可切换，也可把普通源「移入隐私」（决策 22）。
- **关键连带效果（方案 A 自动满足）**：普通模式过滤掉私有 `ServerConfig` 后，
  `SourceFactory.create()` 根本不会构造出这个 SMB 源 → 连不上、扫不到，普通模式零网络痕迹。

### 档二 · 文档/条目级隐私 —— `file_media_items.isPrivate`（Room）

针对「SMB 和本地的视频文档」（`docs/10` §6.3 的 `file_media_items`，当前 schema v3，
加列需 **Migration v3→v4**）。

- 与档一**完全独立**：哪怕某个 SMB 源本身不是隐私（配置可见、照常浏览），里面**特定的几个视频**也能单独标隐私。
- **本地视频（LOCAL）没有 `ServerConfig`**，唯一能藏它的就是这一档 → 列随本次迁移加上，P3 直接复用。
- 在线源（Emby/Jellyfin/飞牛）条目**不需要**这一档。

### 两档共存行为表

| 场景 | 普通模式行为 | 隐私模式行为 |
|------|-------------|-------------|
| SMB/在线源本身隐私（档一） | 整源不可见、不扫、不连（方案 A） | 显出可切 |
| SMB 源普通，某视频文档隐私（档二） | 照常扫源、显示非隐私文档，私文档被过滤 | 全部显示 |
| 本地视频文档隐私（档二） | 不显示该文件 | 显示 |

> **防漏铁律（修正 v1 漏洞）**：进度/历史/续播本就按 `sourceId` 单源查询（不混排），但只要**跨源聚合**或**只持有 `itemId/sourceId` 而无源上下文**的查询（全局历史、全局搜索、聚合续播、通知、推荐），**不能只靠 `sourceId` 过滤**——
> 必须 `JOIN file_media_items`（或在该表冗余 `isPrivate` 列）后按 `isPrivate` 再过滤一次。
> 否则同源内私文档的进度/历史仍会从全局历史漏出。档一（`ServerConfig.isPrivate`）与档二（`file_media_items.isPrivate`）两道过滤都必须落实，缺一不可。

## 四、存储变更与加密

### 4.1 存储改动表（区分「真零迁移」与「有成本迁移」）

| 存储 | 改动 | 成本（**修正 v1 措辞**） |
|------|------|------|
| `ServerConfig`（`servers.bin`） | 加 `isPrivate: Boolean = false` 字段 | **加字段本身零迁移**（DataStore 自版本化，旧记录读时补默认值）—— ✅ 已实现 |
| 私密源敏感字段迁出 | `baseUrl/userId` 等敏感字段移出主文件，仅留 `id/sourceType/name/isPrivate` 壳 + 标记 | **有成本**：需事务（写加密区成功 → 删旧 token → 更新 `isPrivate`），失败回滚（见决策 21） |
| `TokenStore`（凭据） | 私密源令牌/SMB 账号密码**迁出**到隐私加密区，不再入普通 `token_<id>.bin` | **有成本**：同上一事务 |
| `file_media_items`（Room） | 加 `isPrivate INTEGER NOT NULL DEFAULT 0` 列 + `(sourceId, isPrivate)` 索引 | **Migration v3→v4**（需维护 schema json + 迁移测试，见决策 23）—— ✅ 已实现 |
| 隐私加密区（新） | 私密 ServerConfig 敏感字段 + 私密令牌/SMB 账号密码，用独立密钥 + 不同算法 + 盐值加密落盘 | 新文件/新模块，置于 `noBackupFilesDir`（见 §4.3） |

> 小结：v1 把整件事说成「零迁移」**不准确**。准确的表述是：**加布尔字段零迁移，但敏感字段迁出 + 凭据迁移 + Room 加列均有真实迁移成本，且必须是原子事务**。

### 4.2 隐私数据加密格式规范（与普通不一致 — 用户硬要求，P0#4 收紧）

**普通模式基准**（已查源码 `AppModule.kt` / `KeystoreSecretCipher`）：
所有凭据共用一个 `KeystoreSecretCipher`（别名 `myplayer_credentials`，**AES/GCM/NoPadding**，密钥在 AndroidKeyStore，**无用户认证、无盐值**，仅随密文附 12 字节随机 IV）。

**隐私模式**（算法/盐/门控三方面都不同）：

1. **DEK**（数据加密密钥）随机生成，仅在隐私会话期间驻留内存，会话结束即清。
2. DEK 由**三把 KEK 之一**解封（任一即可）：
   - **KEK-PIN**：`PBKDF2-HMAC-SHA256(privacyPIN, salt, N)` → 密钥材料。
     **盐（salt）是独立随机值（16 字节），明文随封装 DEK 存储，但绝非 PIN 本身**（盐=PIN 等同无盐、抗彩虹表失效）。
   - **KEK-BIO**：Keystore 密钥 `myplayer_privacy_auth`，`setUserAuthenticationRequired(true)`（生物/设备密码门控），经 `BiometricPrompt.CryptoObject` 解封。
   - **KEK-DEVICE（恢复钥匙，方案 Y）**：设备锁屏密码经 `KeyguardManager`/`BiometricPrompt(DEVICE_CREDENTIAL)` 确认后，用独立认证门控 Keystore 密钥解封（可用性见 §七.5）。
3. **载荷加密格式（严格 encrypt‑then‑MAC）**：
   - 从 DEK 用 **HKDF** 派生**独立**的 `encKey` 与 `macKey`（禁止用同一密钥又加密又 MAC）。
   - 算法 `AES/CBC/PKCS5Padding`；密文前附随机 **IV**。
   - **HMAC-SHA256（用 `macKey`）覆盖 `AAD ‖ IV ‖ 密文`**；AAD 绑定**用途与对象**，例如 `privacy-payload:v1:server:<serverId>` 或 `privacy-payload:v1:item:<itemId>`，**防止密文在不同用途/对象间互换**。
   - 解密时**先验 MAC（常数时间比较），再解密**；MAC 失败直接拒绝（防 padding oracle）。
4. **DEK 封装文件**也需：版本号头、认证、原子写（先写临时文件再 rename，避免半截文件）；每把 KEK 各自独立 `salt/IV/封装`，互不共用。
5. **KDF 参数与暴力成本**：
   - PBKDF2 100k + 4 位 PIN 离线暴力成本低 → **PIN 至少 6 位**；`N` 按设备校准到 **250–500ms**（启动时 benchmark 选档），或评估 **Argon2id**。
   - UI 做**失败退避**（连续错误递增冷却）。
   - 进一步强化（可选）：把 PIN 派生密钥与 Keystore 门控密钥经 HKDF 混合，降低纯离线暴力成功率。
   - 文档/UI **写明**：方案 Y 把最终保密上限降到**设备密码级**（见 §4.4 威胁模型）。
6. **重设 PIN**：只换 KEK-PIN 封装时，旧封装仍可解同一 DEK → **重设时必须删除旧 KEK-PIN 封装**；更高安全选项是**轮换 DEK 并重加密所有隐私数据**（v1 至少做到删旧封装，升级路径留接口）。

> **删 `privacyPinHash`**（修正 v1 矛盾）：不再单独存 PIN 哈希。PIN 正确性由「KEK-PIN 能否成功解封 DEK」判定，解封失败即拒绝；首次设置只生成 DEK 并分别用 KEK-PIN/KEK-BIO 封装存储。

### 4.3 备份排除（P0#6 扩展）

- 隐私加密区文件（DEK 三份封装、私密配置/凭据密文）置于 **`noBackupFilesDir`**，天然不参与任何自动备份/设备迁移。
- `AndroidManifest` 的 **`dataExtractionRules`** 必须**同时**配置 `cloud-backup` 与 `device-transfer` 两类规则的 `exclude`，确保云端备份**和**换机迁移都不带走隐私区。
- **评估是否排除 Room DB / DataStore / 旧 TokenStore**：若不能整体排除，至少保证——私源敏感元数据（baseUrl/userId）已迁出到隐私区，私文档标题/路径在 DB 中仅以 opaque id 关联或同样加密；普通模式读到的只是 `isPrivate` 标记（见 §4.4 对「存在私源」已知事实的讨论）。
- 明确接受度：**「存在 N 个隐私源」这一事实（id + `isPrivate` 标记）可能被备份带走**——这泄露"有隐私功能"，但不泄露内容。若用户要求连事实都不可备份，则需把整条私有 `ServerConfig` 也移入加密区（普通 `observeAll` 改为不枚举它们），代价是普通模式无法做任何提示、切换逻辑改写。当前默认保留标记可读、内容加密的折中（决策，见 §4.4）。

### 4.4 威胁模型（P1#7 显式写出）

- **防什么**：旁人顺手翻手机 / 借手机时看不到隐私源与私文档配置、看不到内容、截不了图、锁屏不露标题、退出后后台不再播私内容、换机备份不带隐私数据。
- **不防什么**：已 root 设备 / 内存取证 / 恶意无障碍服务 / 系统文件管理器直接看磁盘（档二文件仍在原处，app 层不加密文件本身）。
- **方案 Y 上限**：隐私保密性最终等价于**设备锁屏密码**（KEK-DEVICE 可解 DEK）。能解锁手机者本就能持机，风险可控，但需在 UI/文档明示。
- **已知事实泄露**：普通模式可知"有隐私源存在（数量）"与"有私文档存在"，但不知内容/路径/账号。

## 五、会话生命周期与强清理（P0#1）

### 5.1 进入序列
隐蔽手势 → 验证（生物/PIN/设备密码恢复）→ 解封 DEK 驻留内存 → 加载隐私配置（解密敏感字段）→ 窗口加 `FLAG_SECURE` → 右上角显「隐私中」→ 聚合/切换器纳入隐私源。

### 5.2 退出强清理序列（决策 15，核心 P0）
退后台 / 手动退出 / 进程被杀，必须按顺序执行，**不能只清 DEK**：

1. **停止隐私播放**（暂停/停止 ExoPlayer，释放当前媒体）。
2. **清 MediaSession / 媒体通知**（取消 `MediaSession`、移除 `Notification.MediaStyle`，锁屏/蓝牙/车机不再有会话）。
3. **关连接**：关闭隐私 SMB 会话、文件句柄、OkHttp/连接池中与隐私源相关的连接。
4. **取消费/下载/缩略图任务**：取消本会话触发的 WorkManager/协程下载、SMB 扫描、Coil/Glide 缩略图生成任务（见决策 21）。
5. **清缓存**：清理隐私模式期间产生的缩略图/封面缓存（见 §九.2）。
6. **清内存 DEK 与三把 KEK 封装引用**，归零密钥数组。
7. 回前台直接回到**普通模式首页**（普通模式日常图案锁按 app 原行为，不算双层锁）。

> 若退出时正在播放隐私媒体却只清了 DEK，播放器仍持有句柄继续读、通知/蓝牙仍暴露、后台任务仍跑——这是明确漏洞，必须按上述序列全清。

### 5.3 边界情况（旋转 / 生物弹窗 / 多窗口 / PiP）
- 用 `ProcessLifecycleOwner` + 显式状态机区分「真正退到后台」与「配置变更/系统生物弹窗临时遮挡」，避免 `onStop` 误清或该清不清。
- **隐私模式直接禁用 PiP**（决策 25）；分屏/投屏需有遮罩或退出策略；多用户/工作资料下隐私会话不跨资料共享。

## 六、统一可见性策略（P0#2）

### 6.1 策略层
新增 `PrivacyVisibilityPolicy`（或 `VisibleQuery` 封装），集中持有「当前是否隐私模式」与「`includePrivate: Boolean`」，所有 Repository/DAO 调用**强制**传入，不允许业务层手写 `WHERE isPrivate=0` 散落各处。

- 档一：普通模式枚举 `ServerConfig` 时排除 `isPrivate`，隐私模式全量。
- 档二：所有 `file_media_items` 读取在普通模式默认 `isPrivate=0`；**跨源/聚合查询必须 join 或冗余 `isPrivate` 后再过滤**（修正 v1 漏洞，见 §三铁律）。

### 6.2 全数据入口清单（逐一落实过滤）
首页聚合、续播、最近观看、历史、收藏、播放列表、下载列表、队列、通知、媒体浏览、统计、推荐、搜索、**搜索建议**。每一处要么按 `sourceId` 排除私有源，要么 join `file_media_items` 排除私文档。

### 6.3 单测穷举
写一组「**普通模式不得返回任何私源/私文档**」的断言，覆盖上述每个入口；并反向验证「隐私模式全量可见」。作为回归护栏。

## 七、进入 / 退出 / 恢复流程

### 7.1 首次设置（**修正：删 privacyPinHash**）
1. 已解锁 app → 关于页版本号连点 3 下 → 检测无 DEK 封装 → 进入**设置向导**。
2. 设隐私 PIN（**至少 6 位**，决策 18），输入两次确认。
3. 绑生物识别：设备已录指纹/人脸 → 提示「是否启用快速进入」；无生物模块则跳过。
4. **生成随机 DEK**（内存），分别用 KEK-PIN（PBKDF2+随机盐）与 KEK-BIO（认证门控 Keystore）封装，写入隐私加密区（置于 `noBackupFilesDir`）。**不另存 PIN 哈希**。
5. 设完**直接进入隐私模式**（会话激活），提示「已开启，去添加你的隐私服务器」。
6. 此时服务器管理才显出「添加隐私服务器」入口，填 Emby/飞牛/SMB 隐私账号并标 `isPrivate`（敏感字段落加密区）。

### 7.2 日常进入（凭据已存在）
1. 已解锁 app → 关于页版本号连点 3 下。
2. 弹 `BiometricPrompt`（仅 `BIOMETRIC_STRONG`），成功 → 解封 DEK → 进隐私。
3. 生物不可用/失败/选「用 PIN」→ 自定义 PIN 框：PIN 派生 KEK-PIN 尝试解封 DEK，**成败即校验**（不查哈希），成功 → 进隐私。
4. 进隐私后：聚合与切换器纳入隐私源；窗口加 `FLAG_SECURE`；**右上角常驻「隐私中」标识（双击/确认才退出，决策 24）**。

> 注：`BiometricPrompt` fallback 只能是设备密码，故 PIN 兜底需自建输入框。

### 7.3 退出（决策 A：不叠双层锁）
见 §五.2 强清理序列；回前台直接回普通首页，重进需再次手势+验证。

### 7.4 忘记 PIN 恢复（决策 10，方案 Y）
1. **指纹仍可用**（未重启）→ KEK-BIO 解封 DEK → 进后重设 PIN（重封 DEK，删旧 KEK-PIN 封装）。
2. **指纹不可用（刚重启）但记得设备密码** → 点「忘记 PIN？」→ 设备密码确认 → KEK-DEVICE 解封 DEK → 重设 PIN → **数据不丢**。
3. **指纹不可用且设备密码也忘了** → 超出 app 能力，先解设备锁再走 2。

> 旧隐私数据用 DEK 加密，DEK 解封密钥始终在 KEK-PIN/KEK-BIO/KEK-DEVICE 三者之一；任一可用即可重封，**绝不因忘 PIN 丢数据**（否决方案 X）。

### 7.5 KEK‑DEVICE 可用性设计（决策 19，P0#5）
- **首设检测**：`KeyguardManager.isDeviceSecure()` 与 `BiometricManager.BIOMETRIC_STRONG`；**设备无锁屏 → KEK-DEVICE 不可用**，强提示「忘记 PIN 将无法恢复，请先设置锁屏」或要求先设锁屏再开隐私。
- **设置页恢复钥匙状态检查**：展示「设备锁屏 / 生物 / 恢复钥匙」三态，异常时引导重新绑定。
- **API 级别**：`BiometricPrompt(DEVICE_CREDENTIAL)` + `CryptoObject` 需目标 API 真机矩阵验证（API 30+ 行为更稳）；API < 30 时 `KeyguardManager` 仅能确认用户、**不等同授权 auth‑bound Keystore 解封** → 设计降级（如确认后使用更高熵的受设备凭据保护的密钥，或提高 minSdk）。
- 生物录入变化 / 设备密码更改后，auth‑bound Keystore 密钥可能失效 → 恢复流程要能检测并引导用户重新绑定 KEK-BIO/KEK-DEVICE。

**真机测试发现并修掉的 6 个问题（都是单测覆盖不到的接线/口径问题）**

1. `MainScaffold` 没把 `privacyActive` / `privateSecrets` 传给 `SettingsDestination` → 「移入隐私」永不出现、VM 拿不到加密区。
2. `DetailTopBar(...)` 调用漏传 `onTogglePrivate` / `canMarkPrivate`（走默认 false）→ 锁图标永不出现。
3. SMB 目录是**实时列目录**，不经过 Room 过滤 → 普通模式下私有文件仍在文件夹里；且 `entriesOf` 按策略过滤后分不清「没入库」和「是隐私」→ 新增 `FileCatalogStore.privatePaths()`（只回 path 的布尔集合）。
4. 首页数据是缓存的 → 退出隐私后（源未变时）屏幕上仍留着刚才的私有条目 → `privacyResetSignal` 驱动 `HomeViewModel.refresh()`。
5. **设置子导航的返回栈被 saveable 槽保着**：`subNav`（列表 → 关于）用 `rememberNavController` 存进 `MainScaffold` 的 `SaveableStateProvider(tab.name)`，切 tab 只是移出组合、切回来原样恢复 —— 隐私入口恰在关于页，于是「验完回首页 → 再点设置」直接落在关于页（问题 5 修完才暴露）。修法：设置 tab 的槽 key 带版本号（`tabStateSlotKey`），隐私会话进出（`privacyEnterSignal` / `privacyResetSignal`）时递增，旧槽连同返回栈一起丢弃；其它 tab 用固定 key，滚动位置照旧恢复（`app/.../nav/MainScaffold.kt`，回归测试 `TabStateSlotTest`）。
6. **取消被当成失败**：`HomeViewModel.load` 用 `runCatching` 吞下 `CancellationException` 写成 `error` → 退出隐私后首页整屏红字「无法连接到服务器 · StandaloneCoroutine was cancelled」（换源 / 重拉都会 `loadJob.cancel()`）。改成 `try/catch`，`CancellationException` 原样 rethrow、只把真异常翻成错误态（回归测试 `HomeViewModelTest.加载被取消时不落错误态`，去掉修复该用例会红）。

**仍存在的边界（明确标注，不是遗漏）**

- `getLibraries()` 仍会列出文件夹名：SMB 的「库」= 顶层目录，目录名不等于私有文档内容；按目录隐藏需要逐目录统计，本期不做。
- 首页「我的文件夹」卡片的增删依赖下一次刷新（切源/下拉/重进 App）；已在退出隐私时主动刷新一次，但**标记私有后不立即重排文件夹卡片**。
- 指纹 / 设备密码恢复路径在三星上仍无法验证（该机无系统锁屏密码，`BiometricManager.canAuthenticate(DEVICE_CREDENTIAL)` 返回 NONE_ENROLLED），只能在一加上手测。
- 剪贴板脱敏（Android 13 `ClipData` sensitive）与通知脱敏未做：当前隐私模式没有复制入口，播放通知在隐私模式被 MediaSession 占位元数据覆盖。

## 九、防漏与泄露面清单（P0#3 + P1）

### 9.1 已覆盖（基础）
截图/录屏（`FLAG_SECURE`）、系统分享 / Cast / 存相册（禁用）、锁屏媒体元数据（占位）、最近任务缩略图（空白）、对外出口（C）。

### 9.2 缓存与缩略图（P0#3）
- 隐私模式使用**独立 ImageLoader**（Coil/Glide），退出时清理其磁盘+内存缓存；或私文档**不生成缩略图缓存**。
- 封面/缩略图落盘前确认不进普通缓存目录。

### 9.3 下载 / 离线缓存（P0#3）
- 隐私视频若下载，**存 app 私有目录**（`noBackupFilesDir` 或 `filesDir` 内），避免被媒体库/相册扫描。
- 退出隐私时可选清理；下载/完成通知**脱敏**（不显示私密文件名/路径）。

### 9.4 通知（P0#3）
- SMB 扫描完成、下载完成、播放进度类通知，普通模式可能见到的部分**不得带私密文件名/路径/标题**；隐私模式通知一律脱敏或仅「LimePlayer」。

### 9.5 剪贴板 / 输入法 / Autofill / SavedState / Intent / 日志（P0#3）
- **剪贴板**：隐私模式禁用复制，或 Android 13+ 标记 `ClipData` 为 sensitive。
- **输入法**：隐私模式输入框设 `IME_FLAG_NO_PERSONALIZED_LEARNING`，避免输入法学习隐私标题/路径。
- **Autofill**：SMB 凭据输入框设 `importantForAutofill=no`，防密码管理器记录。
- **SavedState/Intent/导航/Deep Link/日志**：**绝不**把隐私标题、路径、URL 放进 Bundle/Intent/Deep Link/日志；只传 opaque id；崩溃上报脱敏路径/标题，隐私模式关闭网络日志。

### 9.6 P1 体验
- **MediaSession 彻底占位**：队列、MediaBrowserService、Android Auto/车机、蓝牙 AVRCP 返回占位或禁用浏览（不止标题/缩略图）。
- **验证界面防窥**：PIN 输入、首次向导、恢复流程临时 `FLAG_SECURE` 并避免最近任务快照。
- **退出防误触**：右上角「隐私中」双击/确认才退出。
- **多窗口/PiP**：隐私模式禁用 PiP；分屏/投屏/多用户/工作资料明确行为（遮罩或退出）。
- **普通源也禁外发**：隐私模式下普通源同样禁用分享/Cast，UI 明示，避免用户困惑。

## 十、不在 v1 / 后续可扩展

- **隐身播放**：播放不写历史/进度（用户明确不做；但隐私播放仍写，靠统一可见性过滤）。
- **条目级在线源隐私**：给 Emby/Jellyfin/飞牛 条目也加 `isPrivate`（需 `media_items` 加列）。
- **本地源专属标记 UI**：等 P3 本地源实现后补（列已随本次加好）。
- **多隐私源数量上限**：`isPrivate` 每源/每条目一个布尔，天然支持 N 个，不做限制。
- **轮换 DEK 重加密**：重设 PIN 时当前仅删旧封装，升级为轮换 DEK 重加密全部隐私数据（更安全，留接口）。
