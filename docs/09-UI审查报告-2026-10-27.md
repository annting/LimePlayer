### 本轮踩进去又爬出来的两个坑（写下来防止复发）

1. **渐隐层把整页撑爆**：第一版用了 `Box { Row(...); Box(Modifier.fillMaxHeight().width(24.dp)) }`。
   `Box` 高度取子节点最大值，而 `Column` 给子节点的 `maxHeight` 是「剩余高度」→ 那个 24dp 宽的渐隐层
   把整块撑到满屏，**媒体库整页内容变空白**（真机复现）。
   正确写法：`drawWithContent { drawContent(); drawRect(brush=…) }` —— 纯绘制，不参与布局。
2. **详情页滚动后返回键压住分区标题**：返回键常驻在 Box 顶层，内容是**从它底下穿过**的，
   滚到「文件信息」时 42% 半透明圆底直接盖在标题字上。
   改法：`derivedStateOf { scrollState.value > 24 }`，越过阈值才叠一层 72dp 顶部渐变遮罩
   （`background → 86% → 透明`），内容在遮罩下淡出，返回键始终干净。截图 `p1/05-detail-scrim.png` ✅

## 5. 横屏字幕对比度（已修，23:50）

**先纠正一条前提**：`SubtitleStyle.outlineWidthDp` 的**代码默认值本来就是 2dp**，不是 0。
真正的问题是**用户把滑杆拉到 0 之后没有任何兜底**——一加设备上实测存的是
`{"textColorArgb":-18611(浅橙),"outlineWidthDp":0.0}`，于是裸字压在浅色画面上只有 1.08–1.63:1。

**所以没改默认值，改的是渲染层兜底**（改默认值会让「已把它调到 0」的用户莫名其妙变回去）：

- `PlayerTokens.SUBTITLE_FALLBACK_OUTLINE_DP = 1.2f` + `SUBTITLE_FALLBACK_OUTLINE_ALPHA = 0.6f`
- `SubtitleLayer`：`outlineWidthDp <= 0.05` 时按兜底值画一层**淡描边**（粗细 1.2dp、透明度 60%），
  而不是不画 —— 「0 描边」表达的是「不想要硬黑边」，不是「不要可读性」
- 设置页预览卡用同一组常量，保证所见即所得
- 字幕设置「文字样式」卡片加了尾注：*描边调到 0 时，画面里仍会补一层淡描边*

**真机复核**：三星把描边拖到 0 → 预览卡仍有淡描边（与 2dp 只差粗细，不是裸字）；
播放页横屏（画面铺满、浅色墙）截到字幕，白字边缘有清晰深色轮廓，可读 ✅
一加（橙色 + 0 描边）装同版本后由同一兜底覆盖。

## 7. 用户真机反馈两处（2026-10-28 已修）

### 7.1 详情页「路径」行点击高亮两侧留白

**现象**：值被截断时点击可展开全文，但按下高亮只在中间一截，左右各空 16dp。

**根因**：`InfoCard` 把每行包在 `Box(Modifier.padding(horizontal = Dimens.pagePadding))` 里，
`clickable` 落在 Box **内部**的 Row 上 → 可点区域跟着被收窄 16dp。
（不是 ripple 形状问题，是命中区域本身窄了。）

**改法**：删掉那层 Box，把左右 16dp 内边距移进 `LabelValueRow`，且**写在 `clickable` 之后**；
同时去掉行上原来的 `.clip(AppShape.control)` —— 圆角交给 `InfoCard` 的 `clip(AppShape.card)` 统一裁，
否则每行各自 8dp 圆角，高亮在卡片上下边缘会凹进去一块。

**真机证据**（`wm size 720x2400` 强制截断路径，按住截图 `.workbuddy/debug/screens/p4/05-ripple-narrow.png`）：
uiautomator 里该行的可点 bounds = `[48,1147][672,1291]`，与卡片横向 `48–672` **完全重合**；
改之前会从 96 起步。

### 7.2 亮色主题下关闭态开关发黑

**现象**：亮色主题里所有 OFF 开关看着像「黑色胶囊」，压过开启态（品牌绿），视觉重量失衡。

**实测色值**（`02-light-settings-bottom.png` 采样）：
轨道 `#E1E5EC`（`Surface3Light`）、圆点 `#5A6472`（`Text2Light`）、描边 `#C6CCD6`。

**根因**：`AppSwitch` 两套主题共用「`text2` 圆点 + `surface3` 轨道」。
这组在暗色下是对的（浅灰点 + 深轨道），到亮色就变成「近黑圆点压浅灰轨道」——
本质是把暗色的推导直接搬到了亮色，没有做主题分支。

**改法**：`AppSwitch` 关闭态按主题分叉：
- 亮色：圆点 **`#FFFFFF`** + 轨道 `borderStrong` `#C6CCD6` —— 白点在白卡片上不会消失，因为轨道比卡片暗一档（1.55:1），形状边界由轨道给出；
- 暗色：维持 `text2` 圆点 + `surface3` 轨道（未改动）。

**真机证据**：`.workbuddy/debug/screens/p4/03-light-switch-fixed.png`（亮色）、`07-dark-switch.png`（暗色无回归）。

> ⚠️ 这里**偏离了 M3 默认**（M3 亮色 unchecked thumb = `outline`，也是偏深色）。
> 按用户明确要求改成白点，属于品牌层面的选择，不是规范错误。
