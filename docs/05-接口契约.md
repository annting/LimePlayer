# 05 · 接口契约

> 本册是**三方接口的唯一事实来源**：Emby、飞牛影视（Jellyfin 协议）、本机媒体。
> 架构影响见 [`02-技术规范.md`](02-技术规范.md) §1.3，播放协商规则见 §6.1。
>
> **状态标记**：`✅ 已确认` / `⚠️ 待验证（M0）` / `🚫 已废弃`。
> **规则：标记为 ⚠️ 的接口不得进入生产代码路径。**

---

## 1. 通用约定

| 项 | 约定 |
|---|---|
| Base URL 拼接 | `{baseUrl}{prefix}`，`baseUrl` 已去尾斜杠；`prefix` 默认空串（飞牛待 M0 确认） |
| 客户端信息头 | `MediaBrowser Client="…", Device="android", DeviceId="…", Version="…"`；Emby 用 `X-Emby-Authorization` 承载，Jellyfin 用 `Authorization` |
| 后续请求鉴权 | Emby：`X-Emby-Token: <token>`；Jellyfin：`Authorization: MediaBrowser Token="<token>"`（两者待 M0 二选一确认） |
| 图片鉴权 | **走请求头**（由 Coil 注入），令牌不进 URL |
| 播放流鉴权 | `api_key=<token>` 查询参数（交给 ExoPlayer / HLS） |
| 时间单位 | 服务端字段为 **tick（100ns）**；进入领域层即转 `Ticks` |
| 路径前缀 | 相对路径（如 `TranscodingUrl`）**必须**与 `baseUrl + prefix` 拼接后才可用 |
| 局域网自动发现 | **不做**：同一网络下 Emby / Jellyfin 会互相干扰扫描，一律由用户显式添加源 |
| 设备识别 | 连接时探测 `/System/Info/Public`，读 `ServerName` / `Version` / `ProductName`；`ProductName` 含 `fnOS` 或服务器名含「飞牛」→ 按 Jellyfin 差异化处理 |

### 1.1 错误映射

| HTTP | 映射 | UI 文案方向 |
|---|---|---|
| `401` / `403` | `Unauthorized` | 账号或密码错误（登录时）/ 登录已失效（取数时） |
| `404` | `NotFound` | 端口或路径前缀可能不对（连接时）/ 资源已不存在（播放时） |
| `5xx` | `ServerError`（带响应原文） | 服务端错误，可重试 |
| 其他 | `Unknown`（带状态码与原文） | 通用错误 + 可展开的诊断信息 |
| 网络异常（`IOException`） | — | 服务器地址不可达，请检查网络与地址 |

## 2. Emby

### 2.1 设备与登录

| 用途 | 方法 | 路径 | 关键参数 / body | 关键响应字段 | 状态 |
|---|---|---|---|---|---|
| 探测服务器 | GET | `/System/Info/Public` | 无（无需鉴权） | `ServerName` / `Version` / `ProductName` | ✅ 已确认 |
| 登录 | POST | `/Users/AuthenticateByName` | body `{"Username":…,"Pw":…}`；头 `X-Emby-Authorization` | `AccessToken` / `User.Id` / `User.Name` | ✅ 已确认 |

失败分支：密码错误 / 账号不存在 → `401`；请求发送前的地址错误 → 连接失败。（具体状态码以 M0 实测为准，见 §7。）

### 2.2 取库与取数

| 用途 | 方法 | 路径 | 关键参数 | 关键响应字段 | 状态 |
|---|---|---|---|---|---|
| **媒体库列表** | GET | `/Users/{userId}/Views` | `IncludeExternalContent=false` | `Items[].Id / Name / CollectionType / ChildCount` | ✅ 已确认 |
| 条目列表 | GET | `/Users/{userId}/Items` | `Recursive=true` · `IncludeItemTypes=Movie,Series,Episode,Video` · `ParentId={libraryId}` · `Fields=MediaSources,UserData,Genres` · `StartIndex` · `Limit` · `SearchTerm?` | `Items[]` / `TotalRecordCount` | ✅ 已确认 |
| 条目详情 | GET | `/Users/{userId}/Items/{itemId}` | `Fields=MediaSources,UserData,Genres,People` | `BaseItemDto` | ✅ 已确认 |
| 剧集分集 | GET | `/Shows/{seriesId}/Episodes` | `UserId` · `Fields=MediaSources,UserData,Genres,Overview` · `EnableImages`（**详情页 `true` 要缩略图 / 连播 `false` 减体积**） | `Items[]` 的 `ParentIndexNumber` / `IndexNumber` / `Overview` | ✅ 已确认（连播路径已在用） |
| 图片 | GET | `/Items/{itemId}/Images/{Primary｜Backdrop｜Thumb}` | `maxWidth=<size.px>`；鉴权走**请求头** | 图片字节 | ✅ 已确认 |
| **标记已看** | POST | `/Users/{userId}/PlayedItems/{itemId}` | 鉴权头 | 服务端权威 `UserData`（`Played=true`、`PlayCount` 递增、`PlaybackPositionTicks` 归零） | ✅ 标准 4.x 端点 |
| **取消已看** | DELETE | `/Users/{userId}/PlayedItems/{itemId}` | 鉴权头 | 同上（`Played=false`） | ✅ 标准 4.x 端点 |
| **删除条目** | DELETE | `/Items/{itemId}` | 鉴权头 | 204；**权限由服务端逐条下发 `CanDelete`**（响应含 `CanDelete` 字段）——无权限账号返回 401/403 | ✅ 已确认（`CanDelete` 字段在 4.10 响应中） |
| **人物作品** | GET | `/Users/{userId}/Items` | `Recursive=true` · `PersonIds={personId}` · `Fields=MediaSources,UserData` | `Items[]` | ✅ 标准 4.x 端点 |
| **人物头像** | GET | `/Items/{personId}/Images/Primary` | `maxWidth=<size.px>`；鉴权走**请求头** | 图片字节 | ✅ 标准 4.x 端点 |

**约定**：
- 库列表**只走 `/Views`**。用 `Items + IncludeItemTypes=CollectionFolder` 会把非媒体库的普通文件夹一起扫进来。
- 列表查询的 `Fields` **不含 `People`**：演职员数组在数万条的库上是响应体积与解析耗时的主要来源，会抵消分页 / 增量同步的效果。`People` 只在详情页取。
- `userId` 为空时，上述取数接口**必须立即失败**，不允许拼出 `/Users/null/Items`。
- 详情专属字段（`Overview` 简介 / `ProductionYear` 年份）随 `BaseItemDto` 下发，**只用于详情页即时展示、不同步入库**（见 [`02`](02-技术规范.md) §4.2）。若真机实测某一源未下发，则在详情查询的 `Fields` 中显式补上——**此项待真机确认**。

### 2.3 排序能力（服务端）

服务端 `SortBy` 仅支持：`Album / Artist / Budget / CommunityRating / CriticRating / DateCreated / DatePlayed / PlayCount / PremiereDate / ProductionYear / SortName / Random / Revenue / Runtime`。

**不含文件大小 / 码率 / 分辨率** ⇒ 这三类排序必须由客户端完成（见 [`02`](02-技术规范.md) §6.3）。服务端排序只用于减少同步量，**客户端排序是唯一事实来源**。

### 2.4 播放

| 用途 | 方法 | 路径 | 关键参数 | 关键响应字段 | 状态 |
|---|---|---|---|---|---|
| 播放协商 | POST | `/Items/{itemId}/PlaybackInfo?UserId={userId}` | body 含 `DeviceProfile` | `MediaSources[].SupportsDirectPlay / SupportsDirectStream / SupportsTranscoding / TranscodingUrl / Id / Size / Bitrate / Width / Height / VideoCodec / AudioCodec / Container` | ✅ 已确认 |
| 直连 | GET | `/Videos/{itemId}/stream` | `static=true` · `MediaSourceId` · `api_key` | 支持 Range 的字节流 | ✅ 已确认 |
| 转码（HLS） | GET | `/Videos/{itemId}/master.m3u8` | `MediaSourceId` · `api_key` | m3u8 播放列表 | ✅ 已确认 |

**`TranscodingUrl` 是相对路径**（形如 `/videos/<id>/master.m3u8?...`），必须与 `baseUrl + prefix` 拼接后再交给播放器。
**`DeviceProfile`**：客户端在请求里声明支持的容器 / 视频编码 / 音频编码 / 字幕格式，服务端据此决定直放还是转码。三档协商规则见 [`02`](02-技术规范.md) §6.1。

> **实测注记（2026-10-17 真机）**：标准 `DeviceProfile` 字段名生效，协商判定正确。**容器列表必须包含 `avi`**——
> Media3 1.11 内置 `AviExtractor`（H.264/MP4V/MJPEG + MP3），而 Emby 对未声明 avi 的客户端会转码 remux，
> 且其对 AVI 的 remux 在部分文件上失败（`Error writing trailer: Invalid data found` → HTTP 500）；
> 声明 avi 后服务端改判直放，真机播放成功。依据与完整列表见 `DeviceProfile.kt` 的 KDoc。

## 3. 本机媒体（L2）

| 用途 | 方式 | 关键点 |
|---|---|---|
| 枚举视频 | `MediaStore.Video.Media` | API 33+ 用 `READ_MEDIA_VIDEO`，≤32 用 `READ_EXTERNAL_STORAGE`；取标题 / 时长 / 大小 / 宽高 / 路径 |
| 自定义目录 | SAF `ACTION_OPEN_DOCUMENT_TREE` + `takePersistableUriPermission` | 不申请 `MANAGE_EXTERNAL_STORAGE`；目录记录在设置中作为「本地媒体库」 |
| 播放 | `content://` URI | 恒为 `PlaybackPlan.Direct`，无服务器、无转码 |
| 元数据 | MediaStore 字段 | 海报用 `MediaMetadataRetriever` 抽帧或读内嵌封面并缓存；评分 / 演职员等字段留空 |
| 外挂字幕 | 同目录同名 `.srt/.ass/.ssa/.vtt` | SAF 目录用 `DocumentFile.listFiles()`；MediaStore 目录用 `RELATIVE_PATH + DISPLAY_NAME` 反查 |
| 进度 | 仅存本地 Room | 服务端上报为空实现 |

⚠️ **关键代价**：本机文件**没有服务器转码兜底**。NAS 常见的 DTS / TrueHD 音轨、ASS 精细字幕在手机端可能无法解码或还原（应对见 [`02`](02-技术规范.md) §10 R2）。

## 5. 飞牛影视专项

### 5.1 登录方式与落地顺序

| 方式 | 官方依据 | 说明 | 归属 |
|---|---|---|---|
| ① **影视账号密码** | 飞牛帮助文档：可手动填写「影视账号密码」登录 | 影视应用有**独立账号体系**，与 NAS 账号分离；最接近标准 Jellyfin 登录 | **M4 唯一必做路径** |
| ② NAS 账号登录（OAuth 式） | 官方原文：NAS 账号在此起「类似 OAuth」的作用；进入影视登录页选「使用 NAS 账号登录」，打开授权页确认 | 跳转 NAS 授权页 → 用户确认 → 换取影视侧凭据 | L1（需 WebView 承载并捕获回跳） |
| ③ 扫码登录 | 飞牛 TV 文档：飞牛 App → 首页头像 → 更多 → 扫码 → **同意应用账号授权** | 服务端生成二维码 → 飞牛 App 扫码确认 → 客户端轮询取凭据 | L1（接口未公开） |
| ④ NAS 层「授权管理 / 一次性授权码」 | 官方《如何授权 AI Agent 访问 NAS》，需 fnOS 1.2.0800+；授权页默认 HTTPS，IP 访问会提示自签证书 | NAS 账号登录 → 勾选功能 → 确认授权 → 复制一次性授权码 | L1（面向 NAS 能力授权，非影视专有） |

**结论**：飞牛**没有公开的第三方影视开发 API 文档**。M4 只做 ①，它最接近标准 Jellyfin 登录；②③④ 统一后置 L1，**不阻塞 M4**。

### 5.2 M4 登录实现约束

1. 用户输入：`服务器地址(host:8005)` + 影视账号 + 密码。
2. `POST {base}/Users/AuthenticateByName`，body `{"Username":…, "Pw":…}`；请求头按 M0 实测结果二选一。
3. 成功 → 取 `AccessToken` + `User.Id`，**先落盘**（令牌密文存储 + 服务器配置），再构造 `MediaSource`。
4. 失败分支：`401/403` → 账号或密码错误；连接超时 → 地址不可达；`404` → 端口 / 路径前缀可能不对。
5. 若实测发现鉴权头 / 路径与标准 Jellyfin 有差异，**只改 `:source:jellyfin` 的覆盖参数，不动共享骨架**。

## 6. trickplay（缩略图预览）契约

### 6.1 端点

| 用途 | 方法 | 路径 | 状态 |
|---|---|---|---|
| 分片清单 | GET | `/Videos/{itemId}/Trickplay/{width}/tiles.m3u8` | ⚠️ 待验证（Emby / 飞牛各自实测） |
| 单片图片 | GET | `/Videos/{itemId}/Trickplay/{width}/{index}.jpg` | ⚠️ 待验证 |

- Jellyfin 10.9+ 原生支持，**需按媒体库开启并预生成**；Emby 4.8+ 亦有，端点与参数以实测为准。
- 可用宽度档位：`320 / 240 / 160`（待实测哪些返回 200）。

### 6.2 分片清单解析

需要从 `tiles.m3u8` 解析出：

| 信息 | 来源 | 用途 |
|---|---|---|
| 切片分辨率 | `#EXT-X-TILES` 的 `RESOLUTION=WxH` | 渲染尺寸与 `(col,row)` 反算 |
| 每片网格 | 同上 `LAYOUT=NxM` | 同上 |
| 时间间隔 | 同上 `INTERVAL=秒` | `tileIndex = floor(timeMs / intervalMs)` |
| 分片数量 | 播放列表条目数 | 预取范围与越界保护 |

### 6.3 降级链

```
服务端可用 → 用分片预览（零网络、零解码延迟）
服务端不可用 / 本地源 → 仅显示时间气泡
                      → 用户开启「本地生成缩略图」→ 按需抽帧并缓存到应用私有目录
```

## 7. M0 验证清单（待验证项的唯一入口）

> 所有命令在**能访问 NAS 的本机**执行。Windows 下用 `curl.exe`（PowerShell 里 `curl` 是 `Invoke-WebRequest` 的别名，`-i` 会直接报参数错误）。
> 每条结论**必须附证据**（截图 / 原始响应 / 抓包记录），并回写到本册对应章节，把 ⚠️ 改为 ✅。

**前置准备**
- 飞牛地址：`FN_BASE=http://192.168.31.222:8005`（本项目实际环境）

- 抓包工具需能解密 HTTPS；若为自签证书，先在工具中信任

### 6.9 飞牛影视（fnOS Media Center）私有 API —— 2026-10-18 实测结论

> 飞牛影视**不是** Jellyfin/Emby 协议，是自研 API + 签名校验。以下为对着 `192.168.31.222:5666`（fnOS 0.9.8 / mediasrv 0.8.41）实测 + 前端产物逆向的结论。

**鉴权链路**

| 步骤 | 内容 |
|---|---|
| 登录 | `POST /v/api/v1/login`，body `{"username":"…","password":"…"}` → `{"code":0,"data":{"token":"<32位>"}}` |
| 登录后请求头 | `Authorization: <token>`、`x-trim-client: web`、`x-trim-client-version: 631`、`authx: nonce=<6位>&timestamp=<毫秒>&sign=<md5>` |
| 无 Cookie 依赖 | 登录不下发 Cookie；token 即凭证 |

**authx 签名（已用真实样本逐位验证一致）**

```
sign = md5( SECRET + "_" + path + "_" + nonce + "_" + timestamp + "_" + bodyHash + "_" + API_KEY )
SECRET  = "<FN_SECRET>"          // 前端硬编码（/v/assets/14a77ac…js），值见本地 LOCAL_SECRETS.md
API_KEY = "<FN_API_KEY>"     // 前端字节数组 ^169 解出，值见本地 LOCAL_SECRETS.md
GET ：path 不含 query；bodyHash = md5( 参数按 key 排序后 a=1&b=2 )，无参数时 md5("")
非GET：bodyHash = md5( JSON 序列化后的 body )      // ⚠️ 实测用 separators=(',',':')+sort_keys 仍被判 invalid sign，序列化口径待确认
nonce  = 100000~999999 随机（6 位）；timestamp = 毫秒
```

**已确认可用端点**

| 端点 | 方法 | 返回 |
|---|---|---|
| `/v/api/v1/login` | POST | token |
| `/v/api/v1/sys/config` | GET | 系统配置（图片资源、oauth 等） |
| `/v/api/v1/sys/version` | GET | `{"version":"0.9.8","mediasrvVersion":"0.8.41"}` |
| `/v/api/v1/user/info` | GET | 用户信息 + `sources:[{source:"Trim-NAS", source_id:"1000"}]`（媒体源） |
| `/v/api/v1/mdb/list` | GET | **媒体库列表**：`[{guid,name,category,dir_list…}]`（category=Movie 等） |
| `/v/api/v1/item/list` | GET | 需参数（空参返回 `code:-6 Not Found`），参数口径待试 |

**路由判据**：未知路径返回 `501 {"message":"Not Implemented, please update."}`；存在但签名错返回 `{"code":5000,"msg":"invalid sign"}`；存在但业务错返回 `{"code":-6,…}` —— 可据此快速枚举端点。

**下一步待办**：确认 `item/list` 的参数（疑似 source_id + mdb guid + 分页）、找播放地址端点（社区提到 `POST /v/api/v1/stream`）与进度上报端点、确认非 GET 的 body 序列化口径。

**端点目录（来源：官方生态开源客户端 `FNOSP/FlyNarwhal` 的 `lib/core/constants/app_constants.dart`，实测部分已打 ✅）**

**密钥互证（重要）**：FlyNarwhal 常量中的 `defaultApiKey` / `defaultFlyNarwhalApiSecret` 与我们从前端 JS 提取的 `SECRET` / `API_KEY` **完全一致**（具体值不入库，见 `docs/LOCAL_SECRETS.md`，该文件已 gitignore），且它把 `String.fromEnvironment('FLY_NARWHAL_API_SECRET')` 作为**可覆盖入口**（说明密钥确实会随版本变，必须留配置位）。

**结论**：`item/list` 等接口的参数名以 FlyNarwhal 的 `lib/data/datasources/remote/media_remote_data_source.dart` 为准（下一步读取该文件即可定稿，无需再黑盒试参）。

**关键修正与实测（2026-10-18，来自 FlyNarwhal `media_remote_data_source.dart` + 真机实测）**

| 规则 | 说明 |
|---|---|
| **GET vs POST** | `mediadb/list`、`item/{guid}`、`stream/list/{guid}`、`search/list` 是 **GET**（参数放 query）；**`item/list`、`stream`、`play/play`、`play/info`、`play/record` 是 POST（参数放 JSON body）**。签名口径随之一致：GET 用排序后 query 串的 md5，POST 用 `JSON.stringify(body)` 的 md5（紧凑、无空格）。 |
| 载荷位置 | 官方客户端注释明确：**POST 的载荷必须放 body**，放 query 会被判 `invalid sign` |

**✅ 实测通过的完整链路**

```
POST /v/api/v1/login              {"username","password"}      → data.token
GET  /v/api/v1/mediadb/list                                    → [{guid,title,posters[],category}]
POST /v/api/v1/item/list          {"ancestor_guid":"<mdb guid>","page":1,"page_size":20,
                                   "sort_column":"create_time","sort_type":"DESC"}
                                  → {total:3, list:[{guid,title,type,poster_list[],watched,
                                     media_stream:{resolutions[],…},season_number,episode_number,…}]}
```

`item/list` 的 `ancestor_guid` 传媒体库 guid；`type` 为 `Directory`（文件夹/合集）等；`parent_guid` 用于目录下钻；`favorite/list` 同 body 结构。

**待验（下一步）**：`POST /v/api/v1/stream`（StreamRequest：item/media/video/audio guid）→ 播放地址；`POST /v/api/v1/play/play` 换最终可播链接；`POST /v/api/v1/play/record`（进度，字段含 item_guid/media_guid/ts/duration/device_id/…）。

**播放链路实测（2026-10-18，字段定义取自 FlyNarwhal `player_models.dart`）**

```
POST /v/api/v1/play/info   {"item_guid":"<条目 guid>"}
  → data: { guid, media_guid, video_guid, audio_guid, subtitle_guid, ts, play_config{skip_opening,skip_ending} }

POST /v/api/v1/play/play   {"media_guid","video_guid","video_encoder","resolution","bitrate",
                            "startTimestamp","audio_encoder","audio_guid","subtitle_guid",
                            "channels","forced_sdr"}
  → data: { "play_link": "/v/media/<hash>/preset.m3u8" }   ✅ 实测 code:0
```

- `play_link` 是 **相对路径**，需拼 `baseUrl`；形态为 HLS（`preset.m3u8`，服务端转码）
- `POST /v/api/v1/stream` 的 body 只有 `{media_guid, ip?, level?, header?}`（**多传字段会报 Invalid Params**）；实测仅传 media_guid 返回 `code:-1`，推测 `ip` 必填 —— 待补
- 结论：**即使 stream 失败，play/play 也能直接给出可播地址**，可先按此实现

**进度上报** `POST /v/api/v1/play/record` 字段：`item_guid, media_guid, video_guid, audio_guid, subtitle_guid, resolution, bitrate, ts(秒), duration, play_link, device_id, direct_link_audio_index, lan, device_name`

**2026-10-18 追加实测（接入 UI 与真机联调阶段）**

| 项 | 结论 |
|---|---|
| 探测端点 | **`GET /v/api/v1/sys/version` 免签名**（返回 `0.9.8 / 0.8.41`），是唯一可用于「添加服务器 → 测试连接」的公开端点；飞牛**没有** `/System/Info/Public` |
| 条目详情 | `GET /v/api/v1/item/{guid}` → `title / type / can_play / play_item_guid / poster_list / media_stream / is_watched / ts`；`type=Directory`（电影文件夹）时真正可播的是 **`play_item_guid`**，需下钻一层 |
| 海报 | `posters` / `poster_list` 里是相对路径（如 `/d5/07/poster-xxx.webp`），真实地址 = **`{baseUrl}/v/api/v1/sys/img{path}?w=<px>`**，鉴权用**同一个 `Authorization: <token>`**；不带鉴权返回 `{"code":-2,"msg":"Auth Failed"}` |
| 播放流鉴权 | **`play_link`（HLS）同样要 `Authorization` 头**：不带头返回 HTTP 200 + `{"code":-2,"msg":"Auth Failed"}`，ExoPlayer 会把它当播放列表解析失败（黑屏 00:00）。接入时把 headers 塞进 `PlaybackPlan.Direct.headers` |
| `stream` 端点 | 该版本（mediasrv 0.8.41）用 `{media_guid, ip, level}` 一律返回 `{"code":-1,"msg":"Invalid Params"}`，**不可用**；`stream/list/{guid}` 返回空流数组。局域网直连方案需另找 |
| `play/play` 副作用 | 每次成功调用会**在服务端真起一个转码任务**。短时间对同一条 media 反复协商（如列表缩略图 + 播放页各来一次）会**堆积转码进程，最终整个媒体服务接口超时**（实测把 `/login` 都拖到超时）。客户端必须：① 复用协商结果（缓存）；② **绝不在列表/缩略图路径调用 `play/play`** |
