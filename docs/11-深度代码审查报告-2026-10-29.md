# LimePlayer 深度代码审查报告

- 审查日期：2026-10-29
- 审查范围：全局架构 / 依赖 / 启动 → `feature:player`（PlayerScreen 1488 行）→ `core:playback` + `PlaybackService` + `source:smb` → `core:network`/`core:database`/`core:security` + `source:emby`/`httpapi`/`jellyfin`/`fnos`
- 审查方式：五轮分批读取，只以代码为准；每条问题均指向文件/方法并给出可执行修复

---

## 一、结论摘要

- 架构分层清晰（app + 7 core + 5 source + 7 feature，共 20 模块）、90% 纯 Kotlin/Compose、MVVM + StateFlow 单向数据流。
- **安全与隐私实现是亮点**：普通模式 AES/GCM（Keystore），隐私模式 AES/CBC+HMAC encrypt-then-MAC + HKDF-SHA256 派生独立双钥 + 认证门控 KEK（生物/设备密码按次授权），`noBackupFilesDir` 原子落盘，Room 层用 `NOT EXISTS` 关联 `file_media_items` 实现档二隐私过滤。
- **无 P0 阻断级缺陷**。最高优先级是 5 个 P1 中的「假横屏坐标轴错乱」「播放器状态残留」「SmbStreamServer 端口泄漏」——直接关系播放正确性与横屏可用性。
- 主要工程债：`PlayerScreen.kt` 1488 行单文件、导航层越权、`PlayerUiState` 未 `@Immutable`、无混淆/无 BP/无任何监控。

## 三、【问题清单】（按严重度排序）

### P1（高优先，建议本轮内修）

**P1-1【假横屏坐标轴错乱】手势层与视觉坐标系不一致**
- 位置：`feature/player/.../PlayerScreen.kt` L298-300（`rotationZ=90f`）+ L539-627（`GestureLayer`）
- 问题：`graphicsLayer { rotationZ = 90f }` 是纯绘制层变换，**不改 layout**。`GestureLayer` 的 `offset.x`/`dragAmount` 轴向与 `offset.x < size.width/2` 半屏判定全基于 layout 轴；亮度/音量量程用 `size.height`（假横屏下是视觉短边）。
- 影响：视觉上「左右滑」可能被 `detectVerticalDragGestures` 捕获；亮度/音量调节量程错乱。
- 修复：手势层移到旋转 Box 外层接管视觉坐标系，或显式坐标映射。

```kotlin
// 方案：把手势层放旋转 Box 之外，用 offsetInWindow 的视觉坐标
Box {
    Box(Modifier.graphicsLayer { rotationZ = 90f }) { VideoSurface(...) }
    GestureLayer(Modifier.fillMaxSize(), useVisualAxis = true, ...) // 视觉短边当亮度量程
}
```

**P1-2【CROP 退化】2.39:1 宽画幅被父约束截断成 FIT 留黑边**
- 位置：`PlayerScreen.kt` L321-325（`Modifier.width(w).height(w/videoRatio)`）
- 问题：外层已 `requiredSize`，但内层 CROP 用普通 `width/height`，被父约束截断。
- 修复：

```kotlin
Modifier.requiredSize(width, width / videoRatio)  // 原: Modifier.width(...).height(...)
```

**P1-3【Compose 性能】PlayerUiState 未标 @Immutable 且含 List**
- 位置：`feature/player/.../PlayerViewModel.kt` L37-77（`PlayerUiState`）
- 问题：`positionMs` 每帧/每秒 `copy` 回灌，但含 `List<TrackInfo>`/`List<String>` 被判定 unstable → 整页 recompose 无法跳过。
- 修复：标 `@Immutable` 或改用 `ImmutableList`。

```kotlin
@Immutable
data class PlayerUiState(/* ... */)
```

**P1-4【状态残留】prepare() 不重置 speed 与音轨 override**
- 位置：`core/playback/.../Media3PlaybackEngine.kt` L144-160（`prepare()`）
- 问题：视频 A 开 2x 退出播 B，实际仍 2x 但 UI 显示 1x；音轨/字幕 override 串台。
- 修复：

```kotlin
override suspend fun prepare(...) {
    player.setPlaybackSpeed(1f)                 // 重置倍速
    player.trackSelectionParameters =            // 清除 override
        player.trackSelectionParameters.buildUpon().clearOverrides().build()
    // ... 原 prepare 逻辑
}
```

**P1-5【资源泄漏】SmbStreamServer.stop() 从不被调用**
- 位置：`source/smb/.../SmbMediaSource.kt` L77-80（`streamServer` lazy）+ `SmbStreamServer.kt` L82-88（`stop()`）
- 问题：增删 SMB 服务器累积 listen 端口 + daemon 线程；`SmbClients` 有 `MAX_CLIENTS=4`，但 server 无上限。
- 修复：给 `SmbMediaSource` 加 `close()` 委派 `streamServer.stop()`，并在服务器删除链路释放。

## 八、【落地清单】

### 1. R8 混淆

`app/build.gradle.kts`：

```kotlin
release {
    isMinifyEnabled = true
    isShrinkResources = true
    proguardFiles(getDefaultProguardFile("proguard-android-optimize.txt"), "proguard-rules.pro")
}
```

`app/proguard-rules.pro`（只写必要项，多数库自带 consumer rules）：

```proguard
-keepattributes *Annotation*, InnerClasses, Signature, RuntimeVisibleAnnotations, EnclosingMethod
-keep,includedescriptorclasses class app.myplayer.**$$serializer { *; }
-keepclassmembers class app.myplayer.** { kotlinx.serialization.KSerializer serializer(...); }
-keepclassmembers enum * { *; }
-dontwarn jcifs.**
-keep class jcifs.** { *; }
-keepattributes SourceFile,LineNumberTable
-renamesourcefileattribute SourceFile
```

> OkHttp/Coil/Hilt/Room/DataStore/Media3 自带规则，**不要 blanket keep**。启用后跑一轮冒烟（DTO 解析/SMB/图片加载是高风险面）。
