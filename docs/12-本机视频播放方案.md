# 12 · 本机视频播放方案（功能预览与程序设计）

> **状态**：设计稿（2026-10-31，v2 修正：本机是常驻导航 tab，不是可配置的服务器）。目标里程碑：**P3**（对应 `docs/10 §11`；在 `01-功能说明.md` 里标为 **L2 本机视频文件**）。
> **依赖文档**：`docs/10-数据存储方案.md`（文件型源抽象、`file_media_items` / `playback_progress` / `watch_history` / `media_streams`、`FileCatalogStore` / `PlaybackStore`）、`docs/08-SMB源实现方案.md`（LOCAL 的"近亲"，已落地，是本文主要参照）。
> **本文边界**：只讲**理论、流程、功能与边界**。不写实现代码，类名/方法名仅用于定位。
> **一句话定位**：本机视频 = 手机/平板**自身存储**里的视频文件。它是一个**内置、常驻的导航 tab（「本机」）**，**不是需要配置/添加的服务器**（无地址、无账号）。复用 SMB 已验证的文件型底座（表、进度、探测），唯一要重新设计的是：文件访问方式（SAF 授权）、播放 URI 形态（`file://`/`content://`），以及「未授权 → 授权 → 扫出视频文件夹 → 可忽略」的专属交互外壳。

## 1. 功能预览（用户视角）

本机接入后，用户在 App 里能做什么：

| 场景 | 期望行为 | 复用来源 | 状态 |
|---|---|---|---|
| 导航形态 | 底部导航「媒体库」**改名「本机」**；本机是常驻 tab，**不是可添加的服务器**，无地址/账号配置 | 现有导航结构 | 设计 |
| 默认（未授权） | 进入「本机」默认显示**未授权引导**：说明文案 + 「授权」按钮；不扫任何文件、不列任何内容 | 新增空态 | 设计 |
| 点击授权 | 弹出**系统 SAF 授权**（用户选定可访问的视频范围/根目录），`takePersistableUriPermission` 持久化 | SAF | 设计 |
| 授权后扫描 | 异步扫描本机视频文件，**只列出「包含视频的文件夹」**（每个文件夹 = 一个集合/库） | 扫描 + `file_media_items` | 设计 |
| 忽略文件夹 | 在文件夹列表里**勾选 → 设为忽略**（不进媒体库网格）；右上角「⋮」三点 → 查看已忽略列表，可恢复 | 新增忽略存储 | 设计 |
| 日常浏览 | 未忽略的文件夹进网格浏览视频；本地瞬时排序/筛选 | 现有库页/网格 | 设计 |
| 找片 | 搜文件名（中文任意位置子串、拼音全拼/首字母）；本地索引已现成 | `SearchIndex` 管道 | 设计 |
| 播放 | 点开即播，**无需任何代理**；拖动进度条即时 seek | `PlaybackPlan.Direct(file:// 或 content://)` | 设计 |
| 外挂字幕 | 自动发现同目录同名 `.srt/.ass/.ssa/.vtt` 并列出 | 字幕枚举 | 设计 |
| 续播 | 播到一半退出 → 详情页「继续播放」、首页「继续观看」、历史页全部生效 | `playback_progress` / `watch_history` | 设计 |
| 标记已看 / 删除 | 详情页对勾；删除物理删本地文件 | `PlaybackStore` / `FileCatalogStore` | 设计 |
| 隐私 | 标了隐私的文件夹/文件在普通模式下隐藏 | 档二可见性 | 设计 |
| 离线 | 本地文件天然离线，无"服务器不可达"概念 | — | 天然 |

> **与 SMB 的关系**：SMB 是"局域网里另一台机器的文件夹"（需填地址+账号添加服务器），LOCAL 是"这台手机自己的文件夹"（内置 tab，只差一次授权）。两者共用同一套文件型数据模型，差异只在"怎么拿到字节"和"URI 长什么样"。

## 2. 设计原则

1. **复用文件型源抽象，不加表、不改主键**（决策 D2/D4）。
   现有 `file_media_items` 等表已按 `sourceId + 相对路径` 组织，LOCAL 直接落进去，`sourceType = LOCAL` 即可区分。SMB / LOCAL / 未来的 WebDAV 共用一套读写路径。
2. **进度统一由播放层写 `PlaybackStore`，源不各写一遍**（决策 D1）。
   `MediaSource.reportProgress` 只服务"远端服务器"（Emby/Jellyfin/飞牛）；本地进度由 `PlayerViewModel` 侧统一写库。LOCAL 模块里 `reportProgress` 同 SMB 一样是空实现，**不是坑，是既定设计**。
3. **播放 URI 分叉留在源/目录层，播放层不许感知**。
   SMB 需要本地 HTTP 代理把 `smb://` 桥成 `http://127.0.0.1`；LOCAL 不需要——ExoPlayer 原生支持 `file://` 与 `content://`。这一分叉由 `FileLocator.resolvePlayable()` 收敛，播放引擎零改动。
4. **浏览/播放/搜索/详情/播放器 复用现有界面，但「本机」tab 需要专属交互外壳**。
   SMB 接入时首页/库页/搜索/详情/播放/设置零改动（见 `docs/08 §5`）；LOCAL 同样实现 `MediaSource`，一旦授权即复用同一套库页网格、详情、播放器。**区别在**：「本机」是导航上一个常驻 tab，需新增"未授权引导空态 + 文件夹列表 + 忽略管理"这一层外壳（见 §4.1 / §4.6），而 SMB 是"添加一个服务器后才出现"。因此"零 UI 改动"对 LOCAL **不成立**——改动集中在授权态与文件夹管理，不波及播放/浏览核心。

## 3. 文件访问机制选型（理论）

Android 11+ 强制分区存储（scoped storage），"怎么读本地文件"有三条路：

| 方案 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A. SAF（Storage Access Framework）** | 用户用系统选择器选一个目录树（DocumentFile），`takePersistableUriPermission` 持久授权 | 无需 `MANAGE_EXTERNAL_STORAGE`（docs/01 明确拒绝申请）；用户可控范围；跨重启稳定 | 遍历比 `File` 慢；列兄弟节点需走 `DocumentFile` API | **主方案** |
| B. MediaStore | 走媒体库 `ContentResolver` 查视频 | 元数据现成、性能较好 | 只能看到媒体库已索引的；增删文件有时延；写入受限 | 辅助（取时长/缩略图元数据） |
| C. 直接 `File` | `File.listFiles` 扫目录 | 最快 | Android 11+ 对外部存储几乎不可见；不可控 | 仅 app 私有目录，不作主路径 |

**推荐：以 SAF 为默认，MediaStore / 全盘访问按需。**（2026-11-01 定稿见 §3.1：全盘访问作为**可选加速档**落地）
理由：① 默认通道不碰特殊权限，隐私边界清晰、无上架风险；② 用户显式授权，范围可控；③ 持久化授权后体验稳定；④ 想要"整台手机一次搞定"的用户可以自己开全盘访问，两种诉求都满足。

**本机不是"服务器"**：它与 Emby/SMB 那种"填地址 + 账号"的添加流程无关。SAF 授权是「本机」tab 的一次性入口门槛——用户点「授权」即触发，授权结果（tree URI）持久化后，该 tab 从"未授权引导"切到"文件夹列表 + 浏览"。`media_sources` 里 `LOCAL` 这一行**在首次授权成功时才创建**（之前 = 未授权态）。

**本地源唯一的新增风险点 = URI 持久化**：SAF 的 tree URI 若只存在内存，App 重启即失效。必须把它存进 `media_sources.locatorBase`（现有列已预留 `SAF` 类型），下次启动凭授权重建 `DocumentFile`。授权被用户撤销时，tab 回到"未授权引导"并引导重新授权，**不误删 `file_media_items` 行**。

### 3.1 两条读取通道：SAF（默认）与「全盘访问」（可选加速）

2026-11-01 定稿：**两条通道都做**，默认 SAF，「全盘访问」作为可选加速档。
动机来自竞品观察（OPlayer / EV 全能播放器都申请了 `MANAGE_EXTERNAL_STORAGE`）：它们没开权限时
退回 SAF/MediaStore 手动选文件，开了则直接 `File` 扫全盘 —— 说明这两条路本就该并存。

| | **选择文件夹（SAF）** | **全盘访问（`MANAGE_EXTERNAL_STORAGE`）** |
|---|---|---|
| 用户动作 | 系统选择器里逐棵选目录 | 去系统设置开「所有文件访问权限」（特殊权限，**无弹窗**） |
| 读取实现 | `DocumentsContract` + `ContentResolver` | `java.io.File` |
| 播放 URI | `content://…` | `file://…` |
| 覆盖范围 | 仅授权子树；**禁止**选内部存储根 / `Download` 根 / `Android/data` | 整块外部存储，**含 `Download` 根**；仍进不了 `Android/data` / `Android/obb` |
| 速度 | 每层一次 ContentProvider 查询 | 本地目录遍历，快一个量级 |
| 上架风险 | 无 | Google Play 需申报理由，播放器类常被拒；侧载/国内渠道无碍 |

**首次进入的交互（用户定稿）**：页面**中间**并排两张方案卡 —— 上「全盘访问」（主按钮「去开启」）、
下「选择文件夹」（次按钮）；**不自动弹任何系统界面**（有两个选择时自动弹等于把选择藏起来）。
用户一旦走了 SAF，「全盘访问」入口**收进右上角「⋮」管理页**，不再占页面中间。

**换档不丢进度**：两档共用同一套路径语义（`<别名>/<树内相对路径>`）。全盘档的别名是空串
（= 外部存储根），SAF 档的别名是所选目录（如 `Movies`）—— 两边算出的 `mediaKey` 都是
`Movies/沙丘.mkv`，`playback_progress` 天然通用。

**同一时刻只用一条**：全盘权限在手 → 只用 `FileTree`；否则只用 SAF 根。
否则同名目录会被两棵树同时命中，`locate()` 归属二义。SAF 根列表在换到全盘档后**保留不动**，
权限一旦被撤销（或用户关掉），立刻回落到 SAF，不用重新授权。

## 4. 核心流程

### 4.1 授权与扫描（「本机」tab 的核心流程）

本机是导航栏里**常驻**的 tab，**默认未授权**。整个生命周期分四个状态：

```
状态机：未授权 ──(点授权 → 系统 SAF)──▶ 已授权未扫描 ──(自动扫描)──▶ 已扫描(文件夹列表)
                          │                                              │
                          └────────────(撤销授权 / 重装)─────────────────┘ 回到「未授权」
```

1. **未授权（默认）**
   - 「本机」tab 进入即显示**方案选择页**（§3.1）：中间两张卡，「全盘访问」+「选择文件夹」。
   - 此状态下**不扫任何文件、不列任何内容**，也不向 Room 写条目。
   - **未授权只有一个门槛页**（2026-11-01 定稿）：用户取消授权 / 授权失效都**不切页**，
     只在选择页顶部补一行提示（"刚才没有完成授权…" / "已授权文件夹权限失效…"），
     失效时页面底部额外给「前往系统设置」「管理文件夹」。避免"选择页 → 未获得权限页"两道门。
2. **选一条通道**
   - 点「去开启」→ 跳系统「所有文件访问权限」页；回来（ON_RESUME）重新检测，开启即用 `File` 扫全盘。
   - 点「选择文件夹」→ 系统 SAF 选择器（`OPEN_DOCUMENT_TREE`），选中目录后 `takePersistableUriPermission` 持久授权。
   - 之后「全盘访问」入口收到「⋮」里，不占主界面。
3. **授权后扫描**
   - 自动触发**异步、可取消**的扫描：遍历授权树，按视频扩展名白名单（14 种，复用 SMB）过滤。
   - **只产出"包含视频文件的文件夹"列表**（空文件夹 / 纯图片文件夹不出现）——每个有视频的文件夹 = 一个集合（库）。
   - **库发现口径（2026-11-01 修定）**：判断依据是"该目录**直接**含视频"，卡片数量 = 打开后看到的条目数。
     之前的实现是"递归计数 + 只列一层"，导致"显示 12 个、点进去空的"（视频全在子目录里）。
   - **每层都展开**：无论本层有没有视频，都继续往下找（最多 3 层），把真正装视频的子目录单独列成库
     （`DCIM/Camera` → 库名「Camera」）。不能"本层有视频就停"——全盘档根目录常有散落视频，
     一停就再也进不去 `Movies`/`Download` 这些子目录。
   - **OEM 目录识别兜底**：部分厂商的 `DocumentsProvider` 不给目录下发 `MIME_TYPE_DIR`
     （ColorOS 上 DCIM 就是这么"扫不出视频"的）。判定条件补一条：
     `mime 缺失 && 大小 0 && 名字无扩展名` 也按目录处理。
4. **文件夹列表 → 浏览**
   - 扫描得到的文件夹列表展示在「本机」tab；用户**勾选某个文件夹 → 设为「忽略」**，被忽略的文件夹不进入媒体库网格（见 §4.6）。
   - 未忽略的文件夹点进去 = 现有库页网格（复用 SMB 同款 UI），继续复用排序/筛选/详情/播放。
   - **排序 / 筛选入口在页面顶栏**（`⋮` 左侧的三横线图标），与媒体库详情页一致；
     网格里**不再**出现老版的「排序」「筛选」横条（2026-11-01 反馈：那是旧版视觉）。
     本机场景仍隐藏「类型」「仅收藏」两个无意义维度（§任务 3 的兼容处理）。

> 与 SMB/Emby 的"填地址 + 账号密码 + 添加服务器"完全不同：本机**没有服务器概念、没有地址/账号**，"授权"这个动作就等同于"开通本机源"。

### 4.1.1 多根授权（实现"整台手机"的唯一合法路径）

**系统限制（不可绕过）**：Android 11+ 的 DocumentsUI **不允许选中内部存储根**（选根会提示"无法使用此文件夹"），
SAF 一次授权只能覆盖**一棵子树**。因此"本机全部视频"不是"一次授权"，而是**多根授权 + 合并视图**。
默认通道不申请 `MANAGE_EXTERNAL_STORAGE`（这是"不吓人"的默认选择；想一次覆盖整机的用户可以开**全盘访问**，见 §3.1）。

```
根列表（持久化，保序）
  ├─ Movies        ─┐
  ├─ Download      ─┼─▶ 扫描各自子树 ─▶ 文件夹列表合并成一份视图（按文件夹 id 去重）
  └─ DCIM          ─┘
```

**用户流程**（与 §4.1 状态机衔接）：

| 时机 | 交互 |
|---|---|
| 首次进「本机」 | 自动拉起一次 SAF；选完即成为第 1 根 |
| 想覆盖更多目录 | 文件夹列表页右上角 **「＋」** → 再选一个目录 → 该根并入，列表自动刷新 |
| 管理/撤销 | 列表页 **「⋮」** → 「本机文件夹」弹窗：已授权根（可移除、失效标红）+ 已忽略文件夹（可恢复）+「＋ 添加文件夹」 |
| 某一根被系统撤销 | 该根标记「授权已失效」，内容不再参与合并；可移除后重授权 |

**关键设计：路径前缀（合并后仍能唯一标识条目）**
- 条目路径 = `<根别名>/<树内相对路径>`；根别名由 tree URI 的 documentId 推出（`primary:Movies` → `Movies`，卷根 → 空前缀）。
- 例：授权 `Movies` 后 `LimeTest1.mp4` → 路径 `Movies/LimeTest1.mp4`；授权内部存储根则保持原样。
- 这层前缀直接进 `file_media_items.path` / `playback_progress.mediaKey`，**保证两棵根下同名同路径的文件不会共用一条进度**。
- 别名只取决于"授权时选的目录"，不随显示名/排序变化，因此可以安全长期持久化。

**同族根去重（避免前缀二义）**
- `Download` 与 `Download/video`、或卷根与卷内任意目录，属于**互相覆盖**关系：同时保留会让同一文件出现两种前缀写法，进度会串号。
- 规则：写入时同族只保留**最宽**的一根（卷根最宽）；被覆盖的新根直接忽略，不报错。

**与"忽略文件夹"的关系**：忽略是**单文件夹粒度**（§4.6），多根是**整棵树粒度**；两者正交，
忽略路径带根别名（如 `Movies/广告`），移除某根后该根下的忽略项自然失效、不影响其它根。

**已知取舍**
- 需要用户点几次才覆盖多个目录（系统限制导致，非设计缺陷）；
- 合并视图不显示"某根未授权"的占位（避免噪音），只在「⋮」里标失效。

**系统同时禁止授权的目录**（2026-10-31 三星真机实测，全部提示"无法使用此文件夹／为保护你的隐私，请选择其他文件夹"）：
- 内部存储**根**；
- **`Download` 根**、`Android/data`、`Android/obb`（系统把它们当敏感目录）。
- 替代：选它们的**子目录**（如 `Download/电影`、`Movies`、`DCIM`），或让用户自建一个视频目录。

### 4.2 扫描 / 同步（与 SMB 同构）

```
scan(authorizedTree):
   遍历授权树（一层或受控递归，按性能选深度）
   → 按视频扩展名白名单过滤（复用 SMB 的 14 种：mkv/mp4/m4v/avi/mov/wmv/flv/webm/ts/m2ts/mpg/mpeg/iso/rmvb）
   → 归并出「含视频的文件夹」集合（用于 §4.1 第 4 步的列表）
   → 登记 file_media_items：INSERT OR IGNORE（firstSeenAt 只写一次，见 D5）
   → 技术信息探测（时长/编码/分辨率/轨）：首扫或首次进详情时做，结果入库存（"取一次存库"，第二次免读文件头）
   → 合并本地断点 / 历史（PlaybackStore）
   → 标缺失（文件被删 → missingAt，本期只标不删）
```

### 4.3 播放（**无代理**——与 SMB 最本质的区别）

```
用户点条目
   → planPlayback(entry)
   → FileLocator.LocalFile / SafDocument.resolvePlayable()
        = "file:///…"  或  "content://…"
   → 返回 PlaybackPlan.Direct(uri)
   → ExoPlayer 原生读取（支持 Range / seek，无需本地 HTTP 代理）
   → 播放中：PlaybackStore.recordPosition(…) 由播放层统一写断点（每 10s + 停止时）
   → 播完：completed=1，进度清零
```

### 4.4 外挂字幕发现（LOCAL 比 SMB 更简单）

```
枚举视频同目录的同名兄弟文件：
   《片名》.mkv  →  找 《片名》.srt / .ass / .ssa / .vtt
   可选语言标记： 《片名》.zh.srt → 标签"中文"
→ 作为 SubtitleConfiguration 交给 ExoPlayer（content:// 兄弟节点可直接列，无需代理）
→ 复用现有字幕样式设置（字号/颜色/描边/边距）
```
> SMB 的字幕枚举在 `docs/08` 规划过但当前代码未落地；LOCAL 实现时可一并把这条能力补实，且更天然。

### 4.5 进度 / 历史 / 标记 / 删除

- **断点续播**：`PlaybackStore` 统一写；详情页 `resumePositionTicks`、库页进度条、首页「继续观看」、`getResumeItems` 全部自动生效（与 SMB 同源）。
- **标记已看**：写一条 `completed=true` 断点（不变量位置清零、`playCount+1`）；取消即清断点。
- **删除**：`deleteItem` 物理删本地文件（SAF `DocumentFile.delete()` 或 `File.delete()`），成功清本地断点；库存行下轮扫描标缺失。

### 4.6 忽略文件夹（用户可控的可见范围）

- **语义**：扫描列出来的"有视频的文件夹"，用户可逐个标记为「忽略」——被忽略的文件夹**不进媒体库网格**，但其文件仍保留在 `file_media_items`（不删数据，只隐藏）。
- **存储**：新增轻量 `LocalIgnoreStore`（持久化 `{sourceId, folderPath}` 集合），提供 `ignore(path)` / `restore(path)` / `isIgnored(path)` / `ignoredList()`；与档二隐私的 `privatePaths` **相互独立**（隐私是档二开关驱动的隐藏，忽略是用户逐文件夹的偏好）。
- **入口**：
  - 文件夹列表项上的「忽略」操作（勾选 → 忽略）。
  - 右上角「⋮」三点菜单 → 「已忽略的文件夹」页：列出全部已忽略项，可逐项「恢复」。
- **与扫描的关系**：忽略只影响"展示哪些文件夹"，不影响底层扫描与进度；恢复后该文件夹立即重新出现在列表与网格。
  - 恢复动作发生在「⋮」弹窗里，源实例不变 → 页面必须**显式重扫**（不能只靠 `source` 变化），否则恢复完列表还是空的（2026-11-02 真机踩到）。
  - 若所有含视频的文件夹都被忽略，列表空态要**明说是被忽略**并指路「⋮ → 已忽略」，不能和"真的没有视频"共用一句话。

### 4.7 导航与顶栏（与全局一致）

- **返回**：进了文件夹后，系统返回键 / 左上返回按钮**回到文件夹列表**，不退出 App（`BackHandler` 只在这个层级拦截；列表页是 tab 根，交还系统默认行为）。
- **顶栏**：统一用设计系统的 `PageHeader` + `CircleIconButton`（视觉 40dp / 热区 48dp），
  图标一律 **20dp 的 Material 图形**（`BackIcon` / `FilterListIcon` / `MoreVerticalIcon` / `AddIcon`）。
  不要用 `Text("‹")`、`Text("⋮")`、`Text("＋")` 冒充图标 —— 字形的基线、字重、光学大小都跟矢量图标对不上，
  并排时高低不齐（2026-11-01 用户反馈）。
- **排序/筛选入口**：只在「文件夹内」出现，位于「⋮」左侧，与媒体库详情页同一个 `FilterListIcon`。

## 5. 与 SMB 的关键差异

| 维度 | SMB（已落地） | LOCAL（本方案） |
|---|---|---|
| 形态 | 可添加的服务器（填地址+账号） | **常驻导航 tab（「本机」），非服务器** |
| 文件位置 | 局域网另一台机器的共享 | 本机存储 |
| 访问 API | smbj（SMB2/3） | SAF `DocumentFile` / `File` / MediaStore |
| 播放 URI | `http://127.0.0.1:<port>/<token>`（本地 HTTP 代理） | `file://` 或 `content://`（**直出，无代理**） |
| 是否需要端口/线程 | 是（SmbStreamServer） | 否 |
| 授权方式 | 账号/密码/域 | **系统 SAF 一次性授权**（无账号） |
| 默认态 | 添加后才出现 | **默认未授权引导**，授权后才扫 |
| 文件夹管理 | 共享根下顶层目录即库 | **扫出"有视频文件夹"，可逐文件夹忽略** |
| 字幕发现 | 代码未落地 | 直接列兄弟节点，更易实现 |
| 抽帧/海报 | 经代理 `MediaMetadataRetriever` | 直读文件头，原生更快 |
| 离线语义 | 共享可能掉线 | 天然离线，无"不可达" |
| 数据表 | `file_media_items` 等 | **完全共用**（仅 `sourceType` 不同） |
| UI 改动 | 零（已验证） | **有，集中在外壳层**：底部导航「媒体库」→「本机」改名；新增未授权引导空态、文件夹列表、忽略管理（三点菜单）；授权后浏览/播放/搜索/详情复用现有 UI，零改动 |

> 真正需要分叉/新增的代码点 = `FileLocator`（SafDocument 子类型）+ `LocalIgnoreStore`（忽略集合）；其余 browsing/playback 共用。

## 6. 模块与装配改动（最小清单，点到为止）

> 与 SMB 接入时"1 个新模块 + 9 处装配点"同构，但 LOCAL 更轻（无客户端库、无代理、无密码），**且需新增「本机」tab 外壳而非"添加服务器"入口**。

| # | 改动 | 说明 |
|---|---|---|
| 1 | 新增 `:source:local` 模块 + `LocalMediaSource`（实现 `MediaSource`） | 形态照 `SmbMediaSource`：列目录/详情/探测/`planPlayback` 直出 URI/断点/续播/标记/删除/隐私 |
| 2 | `SourceFactory.create` 加 `LOCAL` 分支 | 当前 `else -> null` 已注释 `// LOCAL 在 L2`（`:88`）；凭据从 `media_sources.locatorBase` 取 tree URI，无账号 |
| 3 | `FileLocator` 加 `SafDocument(treeUri, documentUri)` 子类型 | `resolvePlayable()` 返回 `content://`；与现有 `Smb`/`LocalFile` 并列 |
| 4 | **底部导航「媒体库」→「本机」** | 常驻 tab；不是可添加的服务器，无地址/账号配置 |
| 5 | 「本机」未授权引导空态 + 授权按钮 | 默认态：说明 + 授权；点授权走 SAF `OPEN_DOCUMENT_TREE`，成功才建 `LOCAL` 源行并持久化 tree URI |
| 6 | 文件夹列表 + 忽略交互 | 扫描后列出"有视频的文件夹"；勾选 → 忽略 |
| 7 | 右上角「⋮」→ 已忽略文件夹页 | 查看/恢复被忽略的文件夹 |
| 8 | 新增 `LocalIgnoreStore`（忽略集合持久化） | `ignore/restore/isIgnored/ignoredList`；与档二 `privatePaths` 独立 |
| 9 | `AppModule` 注入 tree URI 取回 / `playbackStore` / `fileCatalog` | Hilt 装配，与 SMB 同参复用 |
| 10 | 测试 | `SourceFactoryTest` 加 LOCAL 分支；`LocalMediaSource` / `LocalIgnoreStore` 单测（路径解析、字幕枚举、断点合并、忽略集合） |

**UI 内核（库页网格 / 搜索 / 详情 / 播放 / 设置 / 服务器管理）复用 SMB 同款，零改动**；**新增**集中在「本机」tab 外壳：导航改名、未授权引导、文件夹列表、忽略管理（三点菜单）。

> 旧 `docs/10 §11` 曾建议"本地源先只走 `MediaCatalog` + 新页面"。**该建议已过时**：SMB 已实证 UI 完全源无关，故本方案改为推荐实现 `LocalMediaSource` 复用现有所有界面，仅在外层套一个本机专属的授权/文件夹管理外壳。

## 8. 风险与未决

| 风险 | 影响 | 缓解 |
|---|---|---|
| SAF 列目录慢（大目录 / 深递归） | 首扫卡顿 | 受控递归深度 + 增量扫描（按 `lastModified` 比对）；先接受一次性成本 |
| tree URI 失效（用户撤销授权 / 重装） | tab 回未授权态 | 回到"未授权引导"并引导重新授权；不误删 `file_media_items` 行 |
| Android 13+ 分区存储边界 | 某些路径不可见 | 默认走 SAF；需要更全覆盖时用户自选「全盘访问」（§3.1） |
| **全盘访问的上架风险** | Google Play 需申报理由，播放器类常被拒 | 默认不要求；侧载 / 国内渠道无碍；若上 Play，仅保留 SAF 通道即可（删 manifest 一行） |
| **`file://` 抽帧失败** | 全盘档视频没有预览图 | 抽帧改用 `setDataSource(context, uri)` 重载（2026-11-01 实测：String 重载返回 0xFFFFFFEA） |
| **双通道同时生效** | 同名目录归属二义 | 全盘权限在手时只用 `FileTree`；SAF 根保留但不用，权限撤销即回落 |
| 外挂字幕权限 | 需列兄弟文档 | SAF tree 授权已含子树，可行 |
| 与 SMB 同名文件冲突 | 进度串源 | `sourceId` 隔离，逻辑关联 `sourceId + mediaKey`，互不影响 |
| "有视频文件夹"判定粒度 | 误列空目录 / 漏列 | 只列"直接含视频文件"的目录；纯子目录嵌套可后续支持 |
| **多根合并后同名路径撞车** | 两棵树下 `Movies/沙丘.mkv` 会共用一条进度 | 条目路径带**根别名前缀**（§4.1.1），前缀进 `mediaKey`，天然隔离 |
| **同族根重复授权**（祖先/后代/同一条） | 同一文件出现两种前缀写法，进度串号 | 写入时同族只保留最宽的一根（`aliasCovers` 去重） |
| **移除某根后遗留断点** | 「继续观看」里出现点不开的孤儿 | `getResumeItems` 只返回当前根能解释的 `mediaKey` |
| **系统禁止选根 / Download / Android/data** | 用户以为"选整机"但按钮灰 | UI 不承诺"整机"；引导选子目录，支持多根累加（§4.1.1） |
| 权限声明 | — | **SAF 通道不申请任何运行时权限**；额外声明 `MANAGE_EXTERNAL_STORAGE`（仅用于可选的「全盘访问」档，且必须由用户去系统设置手动开）；沿用已有 `INTERNET` |

## 9. 与现有文档 / 代码的对账

- `core/model/Models.kt:10` 已声明 `SourceType.LOCAL`；`SourceFactory.kt:88` 的 `else -> null` 注释 `// LOCAL 在 L2` 仍是接入点，但**本机实际不走 `SourceFactory`**（它不是 `ServerConfig`，没有地址/账号）：由 `MainActivity` 从 `LocalRootStore` 直接构造 `LocalMediaSource`。
- 本机相关实现落点：`source/local/`（`LocalMediaSource` / `SafTree` / `SafPermission` / `LocalConfig`）、`core/model/LocalTreeKeys.kt`（多根别名规则）、`core/datastore/LocalRootStore.kt`（多根持久化）、`app/nav/LocalScreen.kt`（本机 tab 外壳）。
- `docs/01-功能说明.md`「非目标/不做」表里 SMB 与"本机视频文件"仍标为"不做"——**口径已过时**；另需把底部导航「媒体库」改名为「本机」，实施时一并回填 `01`（文档先行约定）。
- 视频扩展名白名单（14 种）已在 `source/smb/SmbConfig.kt` 落地，LOCAL 直接复用，不必重定义。
- 进度/历史/探测的"取一次存库"机制已被 SMB 真机验证（含 2026-10-31 修复的列表进度条时长兜底），LOCAL 继承即可。
- 忽略文件夹是新增的用户偏好层，与档二隐私 `privatePaths` 语义独立，需新存储（§4.6 / §6 #8）。
